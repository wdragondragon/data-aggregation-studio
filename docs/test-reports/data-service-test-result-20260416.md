# 数据服务模块测试结果

## 1. 测试结论

本次测试基于《数据服务模块测试用例》执行，覆盖数据服务管理接口、开放 API 调用、订阅 Token、调试、监控统计、访问日志、主要用户界面流程和前后端编译验证。

总体结论：有条件通过。

主要链路均可用：数据表模式服务、SQL 模式服务、字段解析、发布/下线、订阅 Token、调试、开放调用、缓存、监控统计、访问日志、权限拦截均通过验证。

当前发现 1 个功能缺陷和 1 个界面一致性问题：

| 编号 | 级别 | 结论 |
| --- | --- | --- |
| DS-API-001 | 中 | Header 参数名不支持连字符，导致 `X-City` 这类常见 Header 名无法配置。 |

## 8. 缺陷详情

### DS-API-001：Header 参数名不支持连字符

| 项目 | 内容 |
| --- | --- |
| 级别 | 中 |
| 影响范围 | 发布参数映射、SQL 模式服务、POST/Header 调用场景 |
| 复现步骤 | 新建或保存数据服务，在发布参数映射中设置参数位置为 `Header`，参数名称填写 `X-City`。 |
| 实际结果 | 后端返回 `BAD_REQUEST`，提示 `Frontend parameter name is invalid: X-City`。 |
| 期望结果 | Header 位置应支持 HTTP 常见 Header 名格式，例如 `X-City`、`X-Request-Id`。 |
| 规避方式 | 暂时使用不带连字符的 Header 名，例如 `XCity`。本次已使用 `XCity` 完成 SQL/POST 补充验证。 |
| 建议 | 对 Header 位置使用 HTTP header token 校验规则；对 Query/Body 参数仍可保留普通标识符约束。 |

### DS-UI-001：调试页返回结果展示与文案不一致

| 项目 | 内容 |
| --- | --- |
| 级别 | 低 |
| 影响范围 | 数据服务编辑页第四步“接口调试” |
| 实际结果 | 点击调试后，返回结果框展示业务 `data` 对象。 |
| 期望结果 | 页面文案为“统一 Result 包装”时，应展示完整 `code/msg/success/timestampe/data`；如果产品只希望展示 data，应同步调整文案。 |
| 建议 | 优先展示完整调试响应，方便测试人员与开放 API 响应结构比对。 |

## 9. 结论与建议

数据服务核心功能已经具备可交付状态，尤其是开放调用、订阅 Token、安全拦截、缓存与监控链路均完成了正向和异常场景验证。

建议在下一轮修复中优先处理 `DS-API-001`。该问题会影响真实业务中常见的 Header 命名习惯；修复后需要回归 SQL 模式服务、POST 服务发布、Header 开放调用三类用例。

`DS-UI-001` 不影响接口运行，但会影响测试人员判断调试响应是否与开放 API 一致，建议随下次界面优化一并处理。
