# 数据质量指标界面测试用例

测试日期：2026-04-15  
测试范围：数据质量 > 质量指标、质量任务、质量任务日志相关入口与联动  
测试环境：本地 `studio-server + studio-worker + Web dev server`

## 测试目标

- 验证“质量指标”菜单、路由和页面首屏可正常访问。
- 验证总览、资产洞察、问题中心三个 Tab 在真实服务下可加载并响应筛选。
- 验证资产抽屉、问题处置抽屉、质量任务日志抽屉和跳转入口行为一致。
- 验证问题中心处置动作不会破坏总览和资产数据刷新。
- 验证无数据、少数据、接口返回空数组时页面有明确空态且无前端异常。

## 前置条件

- 后端 `studio-server` 运行在 `http://127.0.0.1:18080`。
- 后端 `studio-worker` 运行在 `http://127.0.0.1:18081`。
- 前端 Web 运行在 `http://127.0.0.1:5173`。
- 使用默认账号登录：`admin / admin123`。
- 当前项目上下文已选择，可访问数据质量模块。
- 数据库已完成自动升级，存在数据质量相关表：
  - `quality_rule`
  - `quality_task_definition`
  - `quality_issue`
  - `quality_issue_event`
  - `quality_issue_comment`
  - `quality_metric_snapshot`

## 通过标准

- 所有 P0/P1 用例通过：QM-001 至 QM-024。
- 若数据不足导致图表或列表为空，必须显示明确空态且无前端异常。
- 所有处置动作失败时必须有错误提示，成功时必须刷新问题列表或详情。
- 日志查看行为必须与采集任务日志保持一致，使用统一抽屉并保留下载入口。
