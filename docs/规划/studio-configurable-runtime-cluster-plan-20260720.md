# Studio 可配置多集群运行与数据源适用范围

> **注意：本文件是 P0-MC-01 历史实施计划，仅用于追溯第一阶段的设计与验收基线。** 其中 Server 本地执行、`LOCAL` 端点以及 `LEGACY/ENFORCED` 运行模式等内容已被 [P0-MC-02 统一 Worker 执行面与纯控制面计划](./studio-worker-only-execution-plane-plan-20260721.md)取代，不应再作为当前部署或接口联调依据。

**计划编号：** P0-MC-01

**状态：** 实现中（待最终验证）

**更新时间：** 2026-07-21

## 目标

Studio 采用“OMS 统一控制面 + 多个同能力运行集群”的模式。OMS 是唯一的前端和开放 API 入口，也可以执行任务；46、50 和后续集群都是普通的可配置运行集群。集群不表达任务类型能力差异，只表达网络位置，以及哪些数据源可达。

所有集群共享 Studio 数据库。异步任务记录目标集群，由相同集群的 Worker 领取；OMS 对外同步接口保持不变，当前通过本地或受管 HTTP/SLB 路由到实际执行集群。首版不做自动故障转移、流量分配、跨集群工作流节点或跨 Nacos 服务发现。

## 已落地的契约

### 集群与项目授权

- 新增运行集群、运行端点、项目授权、数据源适用绑定和运行配置校验五类持久化对象。
- 集群代码是部署身份，创建后不可修改；部署进程仅配置 `STUDIO_CLUSTER_CODE`。集群地址、HTTP Header、Token、超时和启停由控制面管理。
- 端点模式仅允许 `LOCAL` 或 `HTTP`。URL、Header 值和 Token 经过 `EncryptionService` 加密；读取接口只返回脱敏 URL、Header 名称和 Token 是否存在。
- 多集群项目必须显式授权至少一个集群。单集群环境在没有历史授权时可自动建立默认授权；授权可标注首选集群和是否允许手动运行覆盖。

### 数据源与资源选择

- `DataSourceSaveRequest.applicableClusterIds` 表示数据源人工确认可用的集群集合；连接健康结果只是提示，不能自动改变该集合。
- `GET /api/v1/datasources/options?runtimeClusterId={id}` 仅返回项目可见、启用且适用于指定集群的数据源。共享数据源按“源数据源适用集群”和“接收项目授权集群”的交集处理。
- 任务、工作流、脚本、数据服务、数据接入和协议转换均保存 `runtimeClusterId`。编辑器先选择一个运行集群，再加载数据源、模型和关联资源。
- 资源共享继续保持既有的只读授权语义：接收项目不能手动触发共享采集任务、质量任务或工作流，也不能借助运行集群覆盖扩大执行权限；列表不展示可用的触发入口，后端仍以 `403` 拒绝跨项目触发且不创建运行副作用。
- 变更运行集群必须确认，并清空不再适用的数据源、模型、字段映射、SQL 预览和运行参数缓存；名称、说明和调度等无关字段保留。
- 移除数据源的适用集群前必须展示影响。确认后，引用资源标记为运行配置失效；历史运行继续，新发布、启用、触发和同步调用被拒绝。重新匹配后自动重新校验。
- 资源主列表和详情 DTO 直接返回 `runtimeValid/runtimeValidationMessage`，后端按资源集合批量补齐，不在前端逐行发请求；运维排查仍可使用 `POST /api/v1/runtime-clusters/validations/query`。
- 数据源列表按每个适用集群分别展示 `AVAILABLE/UNAVAILABLE/UNKNOWN`，历史记录查询必须携带集群；健康状态只作为提示，不改变人工适用绑定。

### 定向执行与观测

- `dispatch_task` 固化 `target_cluster_id`、资源修订、claim token 和 Worker boot ID。目标集群恢复前，异步任务保持排队，不转移到别的集群。
- Worker lease 和运行记录保存目标/实际集群，claim、续租和完成以 token、boot ID 和状态做 CAS，避免旧实例覆盖新结果。
- Worker 在 Claim 前和实际执行前都会复核项目集群授权；授权被撤销的排队任务直接失败，避免无效任务长期占据队头。Dispatch 与 Run Record 关联失败会关闭孤立运行记录，恢复流程可按现存关联回退定位。
- 数据服务、接入、协议转换访问日志保存请求集群和实际集群；同步远端不可达返回 `503`，不自动重试，业务 HTTP 状态和响应体保持原样。
- 远端内部执行会建立目标租户/项目上下文并在调用结束后恢复，保证三类同步服务仍按原项目权限、数据源范围和日志归属执行。
- 多集群生产使用共享对象存储保存运行日志；启用服务缓存时使用共享 Redis，不能依赖实例本地缓存。

## 分阶段与验收门槛

| 阶段 | 范围 | 完成条件 |
|---|---|---|
| 1 | 集群登记、端点、项目授权和心跳 | 集群、端点、授权可管理；秘密不回显；OMS 可以登记为运行集群。 |
| 2 | 数据源适用集群和健康隔离 | 数据源可多选适用集群；同一指纹在 A/B 集群可有不同健康状态；移除绑定可预览影响。 |
| 3 | 编辑器和统一校验 | 所有可执行资源先选运行集群；保存、发布、预览、调试和触发都校验授权与数据源绑定。 |
| 4 | 异步定向 | 同库多 Worker 只能领取自身集群任务；旧 Worker 与 `ENFORCED` 模式不混跑。 |
| 5 | 同步远端路由 | OMS 对外地址不变；JSON/XML/SOAP 状态与响应保真；目标不可达为 `503`，日志只写一次。 |
| 6 | 运维、告警、AI 与回归 | 运行、队列、日志、告警可按目标/实际集群过滤；AI 操作不能绕过集群与数据源校验。 |

## 上线与回滚

### LEGACY 到 ENFORCED

1. 备份数据库并执行 `backend/studio-server/src/main/resources/update/20260720/20260720-runtime-cluster.sql`，先以 `STUDIO_RUNTIME_CLUSTER_MODE=LEGACY` 部署兼容 Server/Worker。
2. 建立 `default-local` 记录并授权历史项目；单集群环境将历史数据源、资源绑定到它。多集群环境由管理员创建 OMS/46/50 等记录、项目授权和数据源适用关系。
3. 对历史资源回填运行集群。只有唯一交集时允许给出建议，不能自动猜测多集群资源的可达性。
4. 部署带 `STUDIO_CLUSTER_CODE` 的 Worker，等待心跳和 lease 正常；逐个目标集群测试数据源连接。
5. 排空旧 Worker 和活动任务，核验所有新 Dispatch 都已带 `target_cluster_id`，再切换为 `STUDIO_RUNTIME_CLUSTER_MODE=ENFORCED`。
6. 观察队列、运行记录、同步服务 `503` 和告警。回滚时先关闭强制模式并回退应用，默认保留新增表、列和历史记录，不执行删表。

### 单集群兼容

单集群首次启动自动使用 `default-local`。在 `LEGACY + default-local` 部署身份下，OMS 会安全、幂等地回填历史项目授权、数据源适用绑定和仍为空的资源运行集群；租户只要已有多个集群，或唯一集群不是有效的 `DEFAULT-LOCAL`，就整体跳过而不推断。上线前可通过 `STUDIO_RUNTIME_CLUSTER_BACKFILL_DRY_RUN=true` 只审查候选数量。当项目只有一个已授权、启用的集群时，前端自动选中并将选择器隐藏或只读；接口仍会执行相同的后端校验。因此单集群用户不需要理解多集群概念，也不会因健康状态暂时失败而丢失数据源选项。

## 当前限制和后续工作

- 当前同集群数据源操作和三类同步服务仍保留 Server 本地执行快速路径，Server 也仍需插件目录和运行集群身份；这些执行面分叉不继续扩展，由 [P0-MC-02 统一 Worker 执行面与纯控制面架构](./studio-worker-only-execution-plane-plan-20260721.md)统一收敛。
- 首版只有受管 `LOCAL` 和 `HTTP/SLB` 端点；Nacos 跨集群服务发现是后续适配器，不属于本次交付。
- 不实现自动故障转移、多集群并行、按比例流量调度或节点级跨集群工作流。
- 数据源适用性是人工网络边界，不从连接测试、Worker 心跳或运行失败自动推断。
- 端点和实例管理只服务 Studio 内部调用；不将业务请求 Header、解密 URL、Token 或数据源秘密写入 Dispatch payload、运行记录或访问日志。
- 2026-07-21 人工审计发现的同步代理安全边界已完成代码、定向测试和全量回归：共享 `RuntimeEndpointHeaderPolicy` 统一覆盖正式服务转发、数据源远端调用、端点健康测试和 Worker 最终业务 Header 提取，过滤固定及 `Connection` 动态 hop-by-hop Header、Host、长度 Header 和任意 `X-Studio-*` 保留 Header；Worker Filter 对内部 Token 失败返回 `X-Studio-Internal-Error: INTERNAL_AUTHENTICATION`，对已通过内部认证的 Worker 响应返回 `X-Studio-Runtime-Response: AUTHENTICATED`，OMS 仅保留带正向标记的业务 `401/403`，内部 Token 或 SLB/网关产生的无标记认证失败统一转换为 `503`；端点测试只有收到正向标记的 `2xx` 才成功，端点 Header 密文或 JSON 损坏时健康测试和正式调用均失败关闭；远端 `Location` 会过滤空白/非法值、内部路径、scheme-relative 地址、私网/本机/元数据地址和受管端点的主机或地址别名，仅保留经地址校验的公网绝对地址与非内部相对地址。上述修正仍待真实 HTTP 和正式生产切换验收，具体状态见[当前架构与未完成事项](../交接/studio-multi-cluster-runtime-architecture-20260721.md#201-p0人工审计代码修正状态代码完成待真实验收)。
