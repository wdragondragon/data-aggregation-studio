# 环境初始化说明

本文档用于说明 `data-aggregation-studio` 在新环境部署时如何完成数据库建表初始化和基础数据初始化。

## 初始化内容

环境初始化分为两类：

| 类型 | 执行方式 | 说明 |
| --- | --- | --- |
| 数据库结构初始化 | 执行初始化脚本时自动触发 | 使用 `schema-mysql.sql` 创建或补齐 MySQL 表结构 |
| 基础数据初始化 | 执行初始化脚本 | 写入默认账号、租户、项目、角色权限、插件目录、元数据定义、内置映射规则、内置数据质量规则等基础数据 |

新环境推荐使用一个脚本完成建表和基础数据初始化：

```powershell
cd C:\dev\ideaProject\DataAggregation\data-aggregation-studio\backend
.\scripts\init-studio-data.ps1
```

该脚本运行的是一个非 Web 模式的 Spring Boot 初始化程序，会读取同一套数据库配置，并在初始化基础数据前触发 `schema-mysql.sql`。

MySQL 建表脚本位置：

```text
backend/studio-server/src/main/resources/schema-mysql.sql
```

在线环境基础数据初始化脚本位置：

```text
backend/scripts/init-studio-data.ps1
```

桌面版 SQLite 基础数据初始化脚本位置：

```text
backend/scripts/init-desktop-runtime-data.ps1
```

## 在线 MySQL 环境初始化

### 1. 配置数据库连接

部署前先确认 `studio-server` 指向目标 MySQL 数据库。

PowerShell 示例：

```powershell
$env:SPRING_DATASOURCE_URL='jdbc:mysql://<host>:3306/data_aggregation_studio?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true'
$env:SPRING_DATASOURCE_USERNAME='<user>'
$env:SPRING_DATASOURCE_PASSWORD='<password>'
```

其中：

| 变量 | 说明 |
| --- | --- |
| `SPRING_DATASOURCE_URL` | MySQL JDBC 地址，建议保留 `createDatabaseIfNotExist=true` |
| `SPRING_DATASOURCE_USERNAME` | MySQL 用户名 |
| `SPRING_DATASOURCE_PASSWORD` | MySQL 密码 |

如果未显式配置，当前默认值来自：

```text
backend/studio-server/src/main/resources/application.yml
```

默认读取方式：

```yaml
spring:
  datasource:
    url: ${SPRING_DATASOURCE_URL:...}
    username: ${SPRING_DATASOURCE_USERNAME:root}
    password: ${SPRING_DATASOURCE_PASSWORD:951753}
```

### 2. 执行合并初始化脚本

执行：

```powershell
cd C:\dev\ideaProject\DataAggregation\data-aggregation-studio\backend
.\scripts\init-studio-data.ps1
```

该脚本会先构建 `studio-server` 及其依赖模块，然后运行：

```text
com.jdragon.studio.server.bootstrap.StudioDataInitializerApplication
```

初始化程序启动时会读取以下 schema 配置：

```yaml
spring:
  sql:
    init:
      mode: always
      schema-locations: classpath:schema-mysql.sql
```

因此执行一次 `init-studio-data.ps1` 即可完成建表和基础数据初始化。

### 3. 启动业务服务

初始化完成后，再启动 `studio-server` 和 `studio-worker`。

## 清空后重新初始化

如果是全新的测试环境，但数据库中已有残留脏数据，可以执行重置初始化：

```powershell
cd C:\dev\ideaProject\DataAggregation\data-aggregation-studio\backend
.\scripts\init-studio-data.ps1 -ResetDatabase
```

`-ResetDatabase` 会向初始化程序传入：

```text
--studio.init.reset=true
```

请注意：

| 场景 | 是否建议使用 |
| --- | --- |
| 全新开发环境 | 可以使用 |
| 全新测试环境 | 可以使用 |
| 已确认可丢弃的演示环境 | 可以使用 |
| 已有真实业务数据的环境 | 禁止使用 |
| 生产环境 | 禁止使用，除非已经完成备份并确认要清空 |

`-ResetDatabase` 会清理当前配置数据库中的业务数据后重新灌入初始化数据，执行前必须确认数据库地址没有指向错误环境。

## Linux 或无 PowerShell 环境

如果部署环境不能直接执行 PowerShell 脚本，可以使用 Maven 命令等价执行。

进入后端目录：

```bash
cd /path/to/data-aggregation-studio/backend
```

构建服务模块：

```bash
mvn -pl studio-server -am -DskipTests install
```

执行基础数据初始化：

```bash
cd studio-server
mvn -q -DskipTests org.codehaus.mojo:exec-maven-plugin:3.1.0:java \
  -Dexec.mainClass=com.jdragon.studio.server.bootstrap.StudioDataInitializerApplication \
  -Dexec.cleanupDaemonThreads=false
```

如果需要清空后重置初始化，追加参数：

```bash
mvn -q -DskipTests org.codehaus.mojo:exec-maven-plugin:3.1.0:java \
  -Dexec.mainClass=com.jdragon.studio.server.bootstrap.StudioDataInitializerApplication \
  -Dexec.cleanupDaemonThreads=false \
  -Dexec.args="--studio.init.reset=true"
```

## 桌面版 SQLite 初始化

桌面版运行时使用 SQLite 初始化脚本。

普通初始化：

```powershell
cd C:\dev\ideaProject\DataAggregation\data-aggregation-studio\backend
.\scripts\init-desktop-runtime-data.ps1
```

清空后重新初始化：

```powershell
cd C:\dev\ideaProject\DataAggregation\data-aggregation-studio\backend
.\scripts\init-desktop-runtime-data.ps1 -ResetDatabase
```

桌面版 schema 脚本位置：

```text
backend/studio-desktop-runtime/src/main/resources/schema-sqlite.sql
```

## 推荐执行顺序

在线 MySQL 新环境推荐顺序：

1. 准备 MySQL 实例和目标数据库账号。
2. 配置 `SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME`、`SPRING_DATASOURCE_PASSWORD`。
3. 执行 `backend/scripts/init-studio-data.ps1`，一次性完成建表和基础数据初始化。
4. 启动 `studio-server`、`studio-worker`。
5. 使用默认管理员账号登录后检查租户、项目、权限、插件、规则等基础数据是否可见。

如果确认是可清空的新环境，可将第 3 步替换为：

```powershell
.\scripts\init-studio-data.ps1 -ResetDatabase
```

## 常见问题

### 只启动服务是否会初始化数据？

不会。服务启动会执行数据库结构初始化，但基础数据初始化需要执行：

```powershell
.\scripts\init-studio-data.ps1
```

### 是否必须先启动服务再执行初始化脚本？

不需要。`init-studio-data.ps1` 会启动初始化专用的 Spring Boot 程序，该程序同样会触发 `schema-mysql.sql`，所以新环境可以直接执行初始化脚本。

### 初始化脚本是否会自动建库？

建库能力依赖 JDBC URL 中的：

```text
createDatabaseIfNotExist=true
```

如果数据库账号没有建库权限，请提前创建数据库。

### 重复执行普通初始化会怎样？

初始化程序按内置逻辑写入基础数据，目标是支持重复执行并避免重复造数。若环境已经有手工维护的数据，仍建议先备份后再执行。

### 什么时候使用 `upgrade-studio-schema.ps1`？

`upgrade-studio-schema.ps1` 面向已有环境升级，不是新环境初始化的首选命令。新环境优先使用 `init-studio-data.ps1` 一次性完成建表和基础数据初始化。

## 验证建议

初始化完成后建议检查：

| 检查项 | 预期 |
| --- | --- |
| 后端服务启动 | `studio-server` 无建表异常 |
| 登录 | 默认管理员账号可登录 |
| 租户与项目 | 默认租户、默认项目存在 |
| 权限菜单 | 管理员可看到完整菜单 |
| 插件目录 | 数据源、任务相关插件可见 |
| 元数据定义 | 模型、字段等元数据定义存在 |
| 映射规则 | 内置字段映射规则存在 |
| 数据质量规则 | 内置数据质量规则存在 |
