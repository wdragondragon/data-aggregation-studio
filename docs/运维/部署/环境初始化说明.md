# 环境初始化说明

本文档说明 `data-aggregation-studio` 在 MySQL 与 SQLite 环境下的初始化方式。当前 MySQL 已切换为 SQL-first，首次初始化不再依赖 Spring Boot 自动建表或 Java 引导灌种。

## 初始化入口

| 场景 | 推荐入口 | 说明 |
| --- | --- | --- |
| MySQL 首次初始化 | 手工执行 3 个 SQL 文件 | 先建结构，再灌基础数据和内置数据 |
| MySQL 清空后重置 | `backend/scripts/init-studio-data.ps1 -ResetDatabase` | 仅适用于 schema 已存在且允许清空的环境 |
| 桌面版 / SQLite 测试 | 现有脚本 | 继续走 `schema-sqlite.sql + StudioInitializationService.initialize(true)` |

## MySQL 首次初始化

### 1. 配置数据库连接

部署前先确认 `studio-server` 指向目标 MySQL 数据库。

```powershell
$env:SPRING_DATASOURCE_URL='jdbc:mysql://<host>:3306/data_aggregation_studio?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true'
$env:SPRING_DATASOURCE_USERNAME='<user>'
$env:SPRING_DATASOURCE_PASSWORD='<password>'
```

默认配置文件位置：

```text
backend/studio-server/src/main/resources/application.yml
```

### 2. 依次执行 3 个 SQL 文件

文件位置：

```text
backend/studio-server/src/main/resources/schema-mysql.sql
backend/studio-server/src/main/resources/data-mysql-base.sql
backend/studio-server/src/main/resources/data-mysql-builtin.sql
```

执行顺序固定为：

1. `schema-mysql.sql`
2. `data-mysql-base.sql`
3. `data-mysql-builtin.sql`

含义：

| 文件 | 作用 |
| --- | --- |
| `schema-mysql.sql` | 只创建表结构 |
| `data-mysql-base.sql` | 默认管理员、租户、项目、角色权限、数据源能力目录 |
| `data-mysql-builtin.sql` | 技术元模型、内置字段映射规则、内置质量规则 |

首次初始化推荐在空库执行，不提供“边升级边补历史数据”的兼容语义。

### 3. 启动服务

完成 3 个 SQL 文件后，再启动：

- `studio-server`
- `studio-worker`

应用启动时不再自动执行 `schema-mysql.sql`。如果库里没有预先导入结构和种子数据，服务会直接报缺表或缺基础数据错误。

## MySQL 清空后重置

`init-studio-data.ps1` 现在不再承担 MySQL 首次初始化职责，只保留为“已有 schema 的重置入口”。

执行方式：

```powershell
cd C:\dev\ideaProject\cloud-parent-springboot3\DataAggregation\data-aggregation-studio\backend
.\scripts\init-studio-data.ps1 -ResetDatabase
```

行为固定为：

1. 连接当前配置的数据库
2. 清空 Studio 业务数据表
3. 回放 `data-mysql-base.sql`
4. 回放 `data-mysql-builtin.sql`

约束：

- 必须先执行过 `schema-mysql.sql`
- 只适用于允许清空数据的环境
- 不适用于保留真实业务数据的环境

如果不带 `-ResetDatabase` 且当前库是 MySQL，初始化程序会直接提示改用 3 个 SQL 文件。

## Linux 或无 PowerShell 环境

如果环境不能直接执行 PowerShell，可以等价使用 Maven 调用 reset 程序：

```bash
cd /path/to/data-aggregation-studio/backend
mvn -pl studio-server -am -DskipTests install
cd studio-server
mvn -q -DskipTests org.codehaus.mojo:exec-maven-plugin:3.1.0:java \
  -Dexec.mainClass=com.jdragon.studio.server.bootstrap.StudioDataInitializerApplication \
  -Dexec.cleanupDaemonThreads=false \
  -Dexec.args="--studio.init.reset=true"
```

注意：这同样只适用于 schema 已存在的 MySQL reset，不替代首次 SQL 初始化。

## 验证建议

MySQL 首次初始化完成后建议检查：

| 检查项 | 预期 |
| --- | --- |
| 登录 | 默认管理员 `admin / admin123` 可登录 |
| 租户与项目 | 默认租户、默认项目存在 |
| 数据源能力 | `datasource_type_capability` 已有默认目录 |
| 字段映射规则 | `field_mapping_rule` 共 26 条 |
| 质量规则 | `quality_rule` 系统级共 17 条 |
| 服务启动 | `studio-server` 不再触发自动建表 |

## 常见问题

### 为什么不再推荐 `init-studio-data.ps1` 做首次初始化？

因为 MySQL 首次初始化已经改为 SQL-first。结构和种子数据都以 SQL 文件为准，部署方式更直接，也避免了应用启动时自动建表和 Java 灌数的隐式行为。

### 只启动服务是否会自动建表？

不会。`application.yml` 已关闭 MySQL 的 `spring.sql.init` 自动初始化。

### `schema-mysql.sql` 里现在还有基础数据吗？

没有。该文件现在只保留表结构定义。基础数据和内置数据分别位于 `data-mysql-base.sql`、`data-mysql-builtin.sql`。
