# Studio 分层部署文档

更新时间：2026-08-18

本文是独立交付文档。所有运行配置均按 YAML 文件或 Nacos Data ID 描述，不使用环境变量名替代配置路径。密码、Token 和 AK/SK 在 YAML 中使用占位符，实际交付时由 Secret 管理系统渲染到对应 YAML，不要提交明文。

本文固定前端访问入口为：

~~~text
http(s)://<域名>/dfs/data-aggregation-studio/
~~~

该入口从接入平台 Gateway 的第二层部署开始启用。第一层纯 `studio-server` 只用于建立和验证控制面，不作为生产 Web 对外入口；禁止为了省略 Gateway 而让 Nginx 直接代理 `studio-server:18080`。

浏览器、Nginx、平台 Gateway、Studio Server 和 Worker 的职责边界必须保持如下关系：

~~~text
浏览器
  -> Nginx /dfs/data-aggregation-studio/
  -> 平台 gateway-service /data-aggregation-studio/**
  -> studio-server :18080
  -> studio-worker :18081（只有数据执行请求）
~~~

## 1. 部署形态

gateway-service + studio-server + studio-worker

控制面和数据执行面完整分离，可执行已安装插件支持的任务

~~~mermaid
flowchart LR
    U["浏览器"] --> N["Nginx /dfs/data-aggregation-studio/"]
    N --> G["平台 Gateway /data-aggregation-studio/**"]
    G --> S["studio-server :18080"]
    S --> DB["MySQL"]
    S --> NC["Nacos"]
    S --> W["studio-worker :18081"]
    W --> DS["业务数据源 / 文件源 / MQ"]
    W -.->|能力启用后| OS["OSS / MinIO"]
    W -.->|能力启用后| FG["Flink SQL Gateway :8083"]
    S -.->|能力启用后| R["Redis"]
~~~

本文中的平台 Gateway 是仓库根目录下的 gateway-service。Flink SQL Gateway 是 Flink SQL 数据开发任务的执行入口，只由 Worker 访问，两种 Gateway 不能混用。本文不包含独立智能问数规划服务的部署。

## 2. YAML 配置文件位置

### 2.1 运维使用的启动引导文件

Server 和 Worker 的 Nacos bootstrap 结构：

~~~yaml
spring:
  application:
    name: studio-server
  profiles:
    active: prod
  config:
    import:
      - optional:nacos:studio-server-prod.yaml
  cloud:
    nacos:
      username: <nacos-user>
      password: <nacos-password>
      discovery:
        enabled: true
        server-addr: <nacos-host>:8848
        namespace: ZCYY
        group: ZCYY_GROUP
      config:
        enabled: true
        server-addr: <nacos-host>:8848
        namespace: ZCYY
        group: ZCYY_GROUP
        file-extension: yaml
        import-check:
          enabled: false
~~~

上例是 `studio-server` 的完整 Nacos 引导结构。三个进程的应用名和 Data ID 导入固定映射如下：

| YAML 文件路径 | spring.application.name | spring.config.import |
| --- | --- | --- |
| /opt/data-aggregation-studio/server/application.yml | studio-server | optional:nacos:studio-server-prod.yaml |
| /opt/data-aggregation-studio/worker/application.yml | studio-worker | optional:nacos:studio-worker-prod.yaml |
| /opt/data-aggregation-studio/gateway/application.yml | platform-gateway-service | optional:nacos:zcyy-platform-gateway-service-prod.yaml |

三个 `application.yml` 的 `spring.profiles.active` 固定为 `prod`，`spring.cloud.nacos.discovery.namespace` 和 `spring.cloud.nacos.config.namespace` 固定为 `ZCYY`，两个 group 固定为 `ZCYY_GROUP`。

### 2.2 Nacos Data ID

~~~text
studio-server-prod.yaml
studio-worker-prod.yaml
zcyy-platform-gateway-service-prod.yaml
~~~

配置归属固定如下：

| 配置位置 | 固定职责 |
| --- | --- |
| JAR 同目录的 `application.yml` | 进程名、`prod` profile、Nacos 地址、账号、namespace、group、固定 Data ID 导入 |
| Nacos Data ID | 端口、数据库、业务开关、运行身份、密钥和外部能力参数 |

同一个配置键只能出现在一个位置，禁止依赖覆盖顺序改变最终值。每次部署都更新原 Data ID，禁止新建带日期、版本号或机器名的 Data ID。

### 2.3 重复部署参数规则

每次新部署只替换本文尖括号内的现场值：Nacos 接入地址和账号、MySQL 接入地址和账号、域名、Server/Worker 内部地址以及密码、Token、AK/SK。其余字面值全部保持不变，包括应用名、`prod`、`ZCYY`、`ZCYY_GROUP`、三个 Data ID、服务端口、前端路径和 Gateway 路由前缀。

同一部署的后续升级复用首次部署确定的现场值。接入地址或凭据轮换单独登记变更记录，不与普通版本升级混在同一步骤中修改。

## 5. 接入平台 gateway-service

### 5.1 Gateway Data ID

Nacos Data ID：zcyy-platform-gateway-service-prod.yaml

~~~yaml
auth:
  enable: true

studio:
  gateway:
    route-prefix: /data-aggregation-studio
    exchange-path: /api/v1/auth/gateway/exchange
    shared-secret: <gateway-shared-secret>
~~~

Gateway 认证固定通过 Nacos 服务发现访问 `dfs-service`，`auth.enable` 固定为 `true`，禁止配置 `auth.url` 直连地址。生产环境禁止关闭认证；`false` 会让 Gateway 注入本地模拟 SuperAdmin。

Gateway 必须通过同 namespace/group 的 Nacos 发现 studio-server。平台 Gateway 的动态路由由代码生成，不要在 Nginx 中把请求直接转发到 18080。

Gateway 和 Server 的 shared-secret 必须完全一致，但不能与 internal-api-token、数据库密码或数据源密码复用。两端时钟必须同步。Worker 的 studio.gateway.trust-enabled 始终为 false。

### 5.2 启动和检查

~~~bash
cd /opt/data-aggregation-studio/gateway
java -Dfile.encoding=UTF-8 -jar gateway-service.jar
~~~

检查：

~~~text
http://<gateway-host>:31649/actuator/health 返回 UP
Nacos 中出现 platform-gateway-service 实例
Gateway 能发现 studio-server
~~~

## 6. 固定前端入口和 Nginx 到 Gateway 路由

### 6.1 前端制品基路径

开发交付的 Web 压缩包必须使用以下 base：

~~~typescript
base: '/dfs/data-aggregation-studio/'
~~~

运维不重新编译前端。Web 压缩包解压根目录必须包含 `index.html` 和 `assets/`，并安装到 `/opt/studio/frontend/apps/web/dist/`。禁止把 Web 制品部署到根路径或使用其他前缀访问。正式访问地址只有：

~~~text
http(s)://<域名>/dfs/data-aggregation-studio/
~~~

### 6.2 标准 Nginx 配置

本交付固定使用以下部署参数：

~~~text
前端 dist：/opt/studio/frontend/apps/web/dist
平台 Gateway：127.0.0.1:31649
外部入口：80 或 HTTPS 终止后的 Nginx
~~~

API、OpenAPI、Swagger、原生下载全部经过平台 Gateway；Nginx 不允许直接代理到 studio-server:18080。

~~~nginx
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on;
    keepalive_timeout 65;

    log_format studio_native_download '$remote_addr [$time_local] '
        '"$request_method $uri $server_protocol" $status $body_bytes_sent '
        'request_time=$request_time';

    upstream studio_gateway {
        server 127.0.0.1:31649;
        keepalive 32;
    }

    server {
        listen 80;
        server_name <studio-domain>;
        client_max_body_size 500m;
        client_body_timeout 180s;

        location = /dfs/data-aggregation-studio {
            return 301 /dfs/data-aggregation-studio/;
        }

        location = /dfs/data-aggregation-studio/api/v1/unstructured-management/download/native {
            rewrite ^/dfs/data-aggregation-studio/(.*)$ /data-aggregation-studio/$1 break;
            proxy_pass http://studio_gateway;
            proxy_http_version 1.1;
            proxy_buffering off;
            proxy_cache off;
            proxy_read_timeout 30m;
            send_timeout 30m;
            proxy_set_header Host $http_host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_set_header X-Forwarded-Host $http_host;
            proxy_set_header X-Forwarded-Prefix /dfs/data-aggregation-studio;
            access_log /var/log/nginx/studio-native-download-access.log studio_native_download;
        }

        location ~ ^/dfs/data-aggregation-studio/(api|openapi|v3/api-docs|swagger-ui|swagger-resources|webjars|doc\.html)(/.*)?$ {
            rewrite ^/dfs/data-aggregation-studio/(.*)$ /data-aggregation-studio/$1 break;
            proxy_pass http://studio_gateway;
            proxy_http_version 1.1;
            proxy_buffering off;
            proxy_read_timeout 180s;
            proxy_send_timeout 180s;
            proxy_set_header Host $http_host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_set_header X-Forwarded-Host $http_host;
            proxy_set_header X-Forwarded-Prefix /dfs/data-aggregation-studio;
            proxy_set_header Last-Event-ID $http_last_event_id;
        }

        location /dfs/data-aggregation-studio/ {
            alias /opt/studio/frontend/apps/web/dist/;
            try_files $uri $uri/ /dfs/data-aggregation-studio/index.html;
        }
    }
}
~~~

路由转换示例：

~~~text
浏览器请求：
/dfs/data-aggregation-studio/api/v1/auth/me

Nginx 改写后发给 Gateway：
/data-aggregation-studio/api/v1/auth/me

Gateway 去掉 /data-aggregation-studio 后转给 Server：
/api/v1/auth/me
~~~

Nginx 配置上线前执行：

~~~bash
nginx -t
nginx -s reload
nginx -T
~~~

检查 Nginx 配置输出中不存在 proxy_pass http://...:18080；外部浏览器只能访问 /dfs/data-aggregation-studio/，不能访问 Gateway 的内部地址、Server 18080 或 Worker 18081。

~~~yaml
studio:
  internal-api-token: <internal-api-token>
  encryption-secret: <encryption-secret>

    provider: OSS

    access-key: <oss-access-key>

  plugin-runtime:
    mode: LAZY_OBJECT_STORAGE
    bucket: <bucket>
    prefix: aggregation-plugins
    channel: production
~~~

Worker 的 aggregation-home 固定包含：

~~~text
/opt/data-aggregation/aggregation/conf/core.json
/opt/data-aggregation/aggregation/plugin/source/
/opt/data-aggregation/aggregation/plugin/reader/
/opt/data-aggregation/aggregation/plugin/writer/
/opt/data-aggregation/aggregation/plugin/transformer/
~~~

source 插件用于连接测试、模型发现、预览和 SQL；reader/writer 插件用于采集和写入。Server 不得挂载这些目录。

### 7.2 Server 放行 Worker 运行端点

在 `studio-server-prod.yaml` 中把 Worker 或其内部 SLB 主机加入白名单：

~~~yaml
studio:
  runtime-endpoint:
    allowed-hosts:
      - <worker-internal-host>
    max-response-bytes: 10485760
~~~

`allowed-hosts` 只填写主机名或 IP，不带协议、端口和路径。配置多个 Worker/SLB 主机时逐项列出，并保留已经批准的其他主机；未列入白名单的运行端点会被 Server 拒绝。

### 7.3 控制面登记

1. 在 Studio 系统管理中创建并启用运行集群，编码等于 runtime-cluster-code。
2. 给项目授权该集群，并设置首选集群。
3. 添加 Worker HTTP 基础地址，例如 http://studio-worker.default.svc:18081，不要追加 /internal/runtime。
4. 启动 Worker，等待心跳和 Lease 在线，再测试端点。
5. 为数据源选择适用集群，完成连接测试、模型发现和预览。

首次部署确定 `runtime-cluster-code`、`instance-id`、`worker-code` 和 Worker 接入地址，后续升级复用原值，不重新生成运行身份。Worker 只能领取目标集群明确指向自己的任务。

### 7.4 启动和检查

~~~bash
cd /opt/data-aggregation-studio/worker
java -Dfile.encoding=UTF-8 -jar studio-worker-<release-version>-exec.jar
~~~

检查：

~~~text
http://<worker-host>:18081/actuator/health 返回 UP
Nacos 中出现 studio-worker 实例
Studio 中 Worker 心跳和 Lease 在线
Worker 上报的 runtime-version 和 plugin-fingerprint 与 release-manifest.yaml 一致
~~~

## 8. 每增加一种外部能力的 YAML 增量

### 8.1 新增数据库、MQ 或 HTTP 数据源

不新增 Server 或 Gateway 配置。需要在 Worker 的 aggregation-home 安装对应插件，并从 Worker 放通到目标系统：

| 能力 | Worker 插件目录 |
| --- | --- |
| 数据源连接测试、发现、预览、SQL | plugin/source/<type> |
| 采集读取 | plugin/reader/<type> |
| 采集写入或数据接入 | plugin/writer/<type> |
| 转换和质量处理 | plugin/transformer/<type> |

数据源地址、账号、密码、库名和表名在 Studio 数据源页面配置，保存后由 encryption-secret 加密。不要把业务数据源凭据写进 Server、Gateway 或 Nacos 的公共配置。

### 8.2 Redis

在使用数据服务响应缓存或原生文件下载票据的 `studio-server-prod.yaml` 中，先删除最小配置里的 `spring.autoconfigure.exclude`，再增加：

~~~yaml
spring:
  data:
    redis:
      host: <redis-host>
      port: 6379
      database: 1
      password: <redis-password>
~~~

多 Server 副本必须使用同一个 Redis。文件传输事件本身使用 MySQL Outbox，不依赖 Kafka、RabbitMQ 或 Redis；Redis 只负责一次性下载票据。

### 8.3 OSS / MinIO 共享对象存储

在 Server 和 Worker 的 Data ID 中增加相同的对象存储配置：

~~~yaml
studio:
  object-storage:
    provider: OSS
    endpoint: <oss-endpoint>
    access-key: <oss-access-key>
    secret-key: <oss-secret-key>
    bucket: <pre-created-bucket>
    region: <oss-region>
    create-bucket: false
  run-log:
    storage-type: OBJECT_STORAGE
    object-prefix: studio/run-logs
    object-storage:
      provider: OSS
      prefix: studio/run-logs
  invocation-log:
    enabled: true
    storage-type: OBJECT_STORAGE
    object-prefix: studio/invocation-logs
~~~

生产 bucket 预先创建，运行账号只授予 GetObject、HeadObject 和所需的日志写权限。TaskManager 不配置 OSS 凭据。

### 8.4 Worker 插件 Lazy 模式

在 Worker Data ID 中把本地模式改为：

~~~yaml

  aggregation-home: /opt/studio/aggregation-lazy
  runtime-version: <release-version>
  plugin-runtime:
    mode: LAZY_OBJECT_STORAGE
    bucket: <plugin-bucket>
    prefix: aggregation-plugins
    channel: production
    refresh-interval-seconds: 30
    refresh-jitter-seconds: 10
    cold-load-timeout-seconds: 300
    max-artifact-bytes: 536870912
    max-extracted-bytes: 1073741824
    max-entry-count: 5000
    cache-max-bytes: 10737418240
    retained-releases: 2
  object-storage:
    provider: OSS
    endpoint: <oss-endpoint>
    access-key: <oss-access-key>
~~~

~~~yaml
studio:
~~~

### 8.6 Flink SQL 数据开发

Flink SQL 仍由 Worker 执行。在 `studio-worker-prod.yaml` 中增加：

~~~yaml
studio:
  flink:
    enabled: true
    execution-mode: gateway
    runtime-endpoint: http://<worker-internal-host>:18081
    query-timeout-seconds: 120
    gateway:
      base-url: http://<flink-sql-gateway-host>:8083
      connect-timeout-seconds: 10
      fetch-timeout-seconds: 120
      max-result-pages: 1000
~~~

`runtime-endpoint` 是 Flink TaskManager 回调 Worker 的地址，`gateway.base-url` 是 Worker 访问 Flink SQL Gateway 的地址，不能互换。

开发交付包固定包含 `flink/studio-flink-<release-version>-connector-remote-upload.jar`。运维校验 `SHA256SUMS` 后，将该 connector 放入 Flink `lib`，移出同版本冲突制品，然后重启 JobManager、TaskManager 和 SQL Gateway。这里只安装 connector JAR，不接收、不安装、不启动对应模块的 executable JAR，也不创建额外的 Nacos Data ID。

TaskManager 必须能访问 Worker 的内部 artifact endpoint。TaskManager 不配置 OSS AK/SK；插件制品通过 Worker 的短期 capability 获取。

### 8.7 文件传输和非结构化管理

Server 和 Worker 的 Data ID 都增加：

~~~yaml
studio:
  file-transfer:
    enabled: true
    event-mode: OUTBOX
    event-poll-delay-millis: 250
    event-batch-size: 500
    progress-event-interval-millis: 1000
    replay-max-events: 5000
    event-retention-days: 7
    cursor-stale-hours: 48
    cleanup-interval-millis: 3600000
    cleanup-batch-size: 1000
    cleanup-max-batches: 20
~~~

还必须满足：

- Server 配置 Redis，用于 120 秒一次性原生下载票据。
- Worker 安装 Local、FTP、SFTP、MinIO 或 OSS 对应的 source/reader/writer 插件。
- Worker 能访问源和目标文件系统；源、目标必须属于同一个运行集群。
- Nginx 使用本文第 6 节的原生下载 location，关闭 proxy_buffering，透传 Last-Event-ID，专用 access log 不记录查询串。
- 文件传输事件使用 MySQL Outbox，不配置 Relay、Kafka 或 RabbitMQ。

### 8.8 告警 Webhook

在 Server Data ID 中增加：

~~~yaml
studio:
  alert:
    webhook:
      enabled: true
      allow-http: false
      allowed-hosts:
        - alert-gateway.internal.example
      connect-timeout-seconds: 3
      request-timeout-seconds: 5
      max-response-bytes: 16384
~~~

公网 HTTPS 不需要加入 allowed-hosts；私网目标必须精确列出主机。URL、Header 和 HMAC 密钥在告警通道页面配置并由 encryption-secret 加密。禁止重定向，禁止回环、云元数据和未放行私网地址。

### 8.9 eLink 告警

在 Server Data ID 中增加：

~~~yaml
studio:
  alert:
    elink:
      enabled: true
      service-name: elink-message-integration
      path-prefix: /elink
      connect-timeout-seconds: 3
      request-timeout-seconds: 10
      max-error-response-bytes: 16384
      max-option-response-bytes: 1048576
~~~

eLink Manager 必须使用与 Studio 相同的 Nacos namespace/group 注册服务。Studio 只访问 Manager，不直连真实 eLink；Manager 自己管理真实 eLink 地址和凭据。

### 8.10 私网 HTTP/SOAP 协议转换

在 Worker Data ID 的 studio.runtime-endpoint.allowed-hosts 中增加精确主机：

~~~yaml
studio:
  runtime-endpoint:
    allowed-hosts:
      - protocol-target.internal.example
    max-response-bytes: 10485760
~~~

同时放通 Worker 到下游服务的端口。URL、Header、Token 和 SOAP 配置在 Studio 页面保存，不能由调用方临时提交任意 Worker URL。

## 9. 网络放行

| 来源 | 目标 | 默认端口 | 条件 |
| --- | --- | ---: | --- |
| 浏览器 | Nginx | 80/443 | 唯一外部入口 |
| Nginx | 平台 Gateway | 31649 | 所有 API、OpenAPI、Swagger、下载 |
| Gateway | Nacos | 8848 | 服务发现和配置 |
| Gateway | Server | 18080 | platform route |
| Server/Worker | MySQL | 3306 | 对应进程已部署 |
| Server/Worker | Nacos | 8848 | 当前在线版基线 |
| Server | Worker/SLB | 18081 | 数据执行 |
| Server | Redis | 6379 | 缓存或下载票据 |
| Server/Worker | OSS/MinIO | 443/自定义 | 对象日志、制品、Lazy 插件 |
| Worker | 业务数据源、MQ、文件源 | 目标端口 | 使用对应数据源 |
| Worker | Flink SQL Gateway | 8083 | Flink SQL |
| Flink TaskManager | Worker | 18081 | remote connector |
| Server | Webhook/eLink Manager | 443/服务端口 | 外部告警 |

Server 所在网络 ACL 拒绝业务数据源网段。Worker 内部端口禁止暴露到用户网络。TaskManager 不配置 OSS 凭据。
