# 托管文件生命周期测试用例

## 自动化覆盖

- 文件策略：Keytab 头、krb5 UTF-8 与 include 拒绝、Hadoop XML 与 XXE 拒绝。
- 加密：AES-256-GCM 加解密、明文大小/SHA-256、密文篡改拒绝。
- 本地物化：`managed-file://` 替换为真实本地路径，插件初始化前完成；Resolution 关闭释放租约。
- 灰度兼容：功能关闭时历史本地路径兼容；开启时历史路径阻断；功能关闭但出现 URI 时运行失败。
- 缓存：活跃文件不被清理，释放后可按容量或空闲时间清理。
- 生命周期：引用中删除拒绝、租约阻止对象删除、对象删除失败退避重试。
- Kerberos：不同 Realm 合并；相同 Realm/KDC 冲突、全局参数冲突和非默认 Realm 缺域映射时原子失败。
- Flink：capability 只能下载当前查询引用的文件；下载后校验大小/SHA 并转成本地路径。
- 迁移盘点：只返回数据源标识和字段名，不返回历史路径。

## UI 与运行验收

1. 在 Kafka 数据源启用 Kerberos，上传 Keytab 和 krb5.conf，保存值不可显示为路径或 `managed-file://` 文本。
2. 测试连接成功后，检查 Worker 缓存出现受控本地文件；DataAggregation 插件日志不得出现 OSS 地址或 `managed-file://`。
3. 执行 Kafka 批任务和流任务，租约心跳持续更新；任务结束后租约释放。
4. 对 HDFS/HDFS3 上传 `hdfs-site.xml`、`core-site.xml`、Keytab、krb5.conf，完成连接测试、模型发现和文件任务。
5. 对 Hive3 上传 Keytab 和 krb5.conf，完成连接测试、模型发现和数据开发 SQL。
6. 替换 Keytab 后，新任务使用新文件；已运行任务继续使用原本地缓存。旧文件引用和租约归零 24 小时后删除。
7. 使用两个不同 Realm/KDC 的 Kerberos Kafka 并发执行；二者均成功。
8. 上传相同 Realm 但 KDC 不同的配置，第二个任务在插件初始化前失败，第一个任务不受影响。
9. 普通用户下载返回无权限；项目管理员下载内容与上传文件一致并产生审计。
10. 删除有引用文件返回冲突；取消表单留下的无引用上传文件 24 小时后进入删除流程。
