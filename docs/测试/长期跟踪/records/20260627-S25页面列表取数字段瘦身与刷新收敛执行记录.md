## 本轮发现

1. 首次 API 探测发现 18080/18081 仍运行旧进程，列表接口仍返回详情字段，`/models/summaries` 返回 500。停止旧 Java 进程后，用 IDEA 配置重启 server/worker，健康检查恢复 `UP`。
2. 重启当前代码后，主要列表接口已不再返回详情大字段，但 `/datasources` 仍为 23.7KB/6 rows。代码确认列表 DTO 不含连接参数和业务元数据，体积主要来自 `recentConnectionTests` 每行 10 条完整历史明细。
3. SDK 中 `datasources.list()` 仍声明为 `DataSourceDefinition[]`，容易让前端误把列表结果当详情使用。
4. 多个列表页发布/下线/上线后仍调用整页列表刷新：
   - 数据服务发布/下线
   - 数据接入服务发布/下线
   - 协议转换服务发布/下线
   - 采集任务上线
   - 工作流发布
   - 数据源保存后重新加载数据源、元模型 schema、能力矩阵

## 修复内容

1. 新增 `DatasourceConnectionTrendPointView`，数据源列表 `recentConnectionTests` 只返回 `status/testedAt/endedAt`。
2. `DataSourceService.toListView` 将完整连接测试记录映射为轻量趋势点；历史弹窗仍通过 `connection-history` 下钻接口获取完整记录。
3. SDK 新增 `DataSourceListView` 与 `DatasourceConnectionTrendPointView`，`datasources.list()` 返回类型改为 `DataSourceListView[]`。
4. 依赖 `datasources.list()` 的页面和组件改用 `DataSourceListView`，详情/表单仍用 `DataSourceDefinition`。
5. 数据源保存后使用返回值局部 upsert 当前列表行，不再整页 `loadPage()`。
6. 数据服务、数据接入服务、协议转换服务、采集任务、工作流的发布类动作改为 patch 当前行；删除类动作仍刷新列表，因为分页总数会变化。
