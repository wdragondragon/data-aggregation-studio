## 代码核对结论

- 数据服务开放 API 成功响应统一 `Result.success(...)`，下线后由 `DataServiceService.invoke` 按 `ONLINE` 状态拦截。
- 数据接入开放 API 成功响应直接写出 `DataIngestionInvokeResult`，失败响应写出 `Result.error(...)`；首跑批次 `20260621230542` 的 FAIL 是探针误把裸成功响应当异常，非产品缺陷。
- 接入服务下线后开放 API 由 `DataIngestionService.invoke` 按 `ONLINE` 状态拦截，未写入半成品。
- 质量任务没有显式下线接口，本轮只覆盖 `online/trigger` 交错；已有 S08 负责单对象手动触发并发去重。
