## 发现的问题

多个页面只需要数据源选项字段，却复用 `GET /datasources` 表格列表接口：

1. `/collection-tasks/new`
   - 源/目标数据源下拉只用 `id/name/typeCode`，并根据 `typeCode` 加载 reader/writer runtime schema。
   - 不需要 `connectionStatus/recentConnectionTests/lastConnectionTestMessage` 等表格健康字段。

2. `/data-ingestion-services/new`
   - 写入目标数据源下拉只用 `id/name/typeCode`，按类型筛选 writer。
   - 不需要连接健康、探测历史、超时配置。

3. `/protocol-conversions/new`
   - HTTP 目标数据源下拉只用 `id/name/typeCode`。
   - 不需要连接健康趋势。

4. `/workflows/new`
   - 工作流节点参数选项只需要数据源名称。
   - 不需要完整表格视图。

5. `/models`
   - 模型中心筛选、同步和手工建模只用 `id/name/typeCode/schemaVersionId/enabled/executable`。
   - 模型详情和字段元数据已经通过模型详情/元模型详情接口按需下钻。

6. `/statistics`
   - 统计工作台筛选只用数据源选项字段。
   - 不需要数据源连接健康或探测历史。

旧 `GET /datasources` 对数据源表格页仍然合理，因为表格需要连接状态、趋势、测试入口和连接历史入口。因此本轮不修改原接口语义，而新增轻量选项接口替代编辑/筛选页调用。

## 本轮整改

1. 新增轻量接口
   - `GET /api/v1/datasources/options`
   - 返回 `DataSourceOptionView[]`：`id/tenantId/projectId/deleted/createdAt/updatedAt/name/typeCode/schemaVersionId/enabled/executable`。

2. 源头查询约束
   - 新增 `DataSourceService.listBasicOptions()`。
   - 只 select 选项字段。
   - 不读取 `connection_fingerprint/connection_status/last_connection_test_*/*_timeout_seconds/technical_metadata/business_metadata`。
   - 不调用 `DatasourceConnectionHealthService.hydrateListViews()`，不查询连接健康和趋势记录。

3. 前端调用调整
   - `/collection-tasks/new`
   - `/data-ingestion-services/new`
   - `/protocol-conversions/new`
   - `/workflows/new`
   - `/models`
   - `/statistics`

以上页面的数据源选项统一改为 `studioApi.datasources.options()`，并把相关组件类型从 `DataSourceListView` 收敛为 `DataSourceOptionView`。
