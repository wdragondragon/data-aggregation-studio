# S65 系统管理直达 Tab 认证恢复补加载执行记录

## 背景

- 日期：2026-06-29
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio/system`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：补验 S64 系统管理分页运行态时，复核 `/system?tab=...` 直达页面是否能在认证和上下文恢复后自动加载当前表格。

## 发现的问题

在 build 后 nginx 入口直达系统管理部分 tab：

- `/system?tab=users`
- `/system?tab=registrationRequests`
- `/system?tab=tenants`
- `/system?tab=projects`
- `/system?tab=tenantMembers`
- `/system?tab=projectMembers`
- `/system?tab=requests`

页面可以进入目标 tab，但首轮加载可能发生在认证、角色或租户/项目上下文尚未恢复完成前，表格显示 `共 0 条`。点击页面“刷新”后数据恢复，例如：

- `用户管理` 手动刷新后显示 `共 17 条`
- `租户` 手动刷新后显示 `共 2 条`

这不是后端分页接口问题，S64 的 7 个 `/page` 接口通过 nginx API 探针均返回正确分页结果。问题在前端直达页面的初始化时机：`activeTab`、`onMounted`、认证和上下文恢复之间缺少一次当前 tab 级补加载。

## 本轮整改

- `SystemView.vue` 新增 `requestCurrentTabReload()`。
- 该方法只刷新当前 active tab，并用 `pendingCurrentTabReload` 对同一 tick 的认证、角色、上下文和路由变化做去重。
- 认证恢复、超级管理员角色恢复、租户/项目上下文变化、active tab 变化和页面 mounted 后均通过该方法触发当前 tab 补加载。
- 没有引入整页刷新，也没有扩大写操作后的刷新范围。
