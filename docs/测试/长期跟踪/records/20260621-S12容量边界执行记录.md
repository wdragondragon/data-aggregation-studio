## 发现并修复的问题

### BUG-S12-001 数据接入慢写响应与副作用不一致

- 严重级别：高。
- 复现批次：`S12-TIMEOUT-VERIFY-20260621B`、`20260621235340`。
- 复现步骤：
  1. 使用 `长期回归-S12客户边界批量接入服务` 调用开放 API，一次提交 500 行。
  2. 等待约 10 秒。
  3. 观察 API 返回 HTTP 500，消息为 `Data ingestion write timed out after 10000 ms`。
  4. 继续等待并查询 `lt_reg_s12_boundary_ingest`。
- 修复前实际：
  - API 返回失败。
  - MySQL 对账：`LT-S12-TIMEOUT-VERIFY-20260621B-*` 最终 500 行，`LT-S12-ING-20260621235340-*` 最终 500 行。
  - 这会让调用方重试并产生重复主键，且调用日志表达与真实副作用不一致。
- 根因：
  - `DataIngestionExecutionSupport.startAndAssertJob` 将同步的 `JobContainer.start()` 包在 `Future` 中。
  - 10 秒 `TimeoutException` 后执行 `future.cancel(true)` 并直接抛 500。
  - 实际 writer 线程可能继续提交，造成响应失败但数据已落库。
- 修复：
  - 将固定超时改为慢写阈值 `DEFAULT_WRITE_SLOW_THRESHOLD_MS`。
  - 超过阈值只记录 warning，然后继续等待 `JobContainer` 最终完成，再依据最终状态返回成功或失败。
  - 中断仍取消并返回中断错误，执行异常仍返回清洗后的失败消息。
- 修复文件：
  - `backend/studio-infra/src/main/java/com/jdragon/studio/infra/service/DataIngestionExecutionSupport.java`
  - `backend/studio-test/src/test/java/com/jdragon/studio/infra/service/DataIngestionInvocationLogSupportTest.java`
- 回归测试：
  - 新增 `shouldWaitForSlowSuccessfulWriteBeyondThreshold`，用慢成功 `JobContainer` 验证超过阈值后等待最终成功。
