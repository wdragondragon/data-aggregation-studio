## 缺陷与修复

| 编号 | 问题 | 代码确认 | 修复 | 回归 |
|---|---|---|---|---|
| M09-FIX-01 | 项目普通成员可直接访问 `/api/v1/roles`、`/api/v1/permissions` 并新增角色/权限 | `RoleController`、`PermissionController` 原先直接访问 mapper，缺少角色校验 | 两个 Controller 注入 `StudioSecurityService`，list/save/delete 均要求 `SUPER_ADMIN` | 单测、实服 API 均验证低权限返回 `403 FORBIDDEN` |
| M09-FIX-02 | 注册页/API 允许对已存在用户名提交注册申请 | `UserRegistrationRequestService.submit()` 原先未在提交阶段校验用户名是否存在 | submit 阶段检查现有用户，重复用户名直接返回 `BAD_REQUEST` | 单测、实服 API 均验证 `admin` 重复注册返回 `400 Username already exists` |
| M09-FIX-03 | 禁用用户登录返回 HTTP 500 | `AuthenticationException` 未被全局异常处理映射 | `GlobalExceptionHandler` 新增 `AuthenticationException` 处理，返回 `401 UNAUTHORIZED` | 单测、实服 API 均验证禁用用户登录返回 `401` |
| M09-FIX-04 | 前端菜单隐藏系统管理，但直接访问 `/system` 缺少路由级角色约束 | 路由 meta 未声明系统管理角色要求 | `/system` 路由增加 `requiredRoleCodes`，路由守卫支持通用角色校验 | `npm run build:web` 通过；admin 浏览器访问 `/system` 正常 |
