## 本轮发现

1. S26 已把 `GET /quality-rules`、`GET /quality-tasks`、`GET /quality-tasks/online` 的响应 DTO 改为轻量列表视图，但服务层查询源头仍未显式限制字段。
2. `QualityRuleService.list()` 仍通过 `quality_rule` 整行查询后组装 `QualityRuleListView`，会读取列表不需要的 `description`、`supported_datasource_types_json`、`logic_sql`。
3. `QualityTaskService.list()` 和 `QualityTaskService.listOnline()` 仍通过 `quality_task_definition` 整行查询后组装 `QualityTaskListView`，会读取列表和工作流候选不需要的 `where_clause`、`resolved_sql_preview`、`parameter_bindings_json`、`rule_snapshot_json`。
4. 前端列表编辑入口已通过 `/quality-rules/{id}`、`/quality-tasks/{id}` 下钻获取完整详情；工作流质量任务候选只使用任务摘要字段，因此列表接口不需要预载详情列。

## 修复内容

1. `QualityRuleService.list()` 增加 `selectRuleListColumns(...)`，只选择表格展示、筛选结果组装、权限判断和创建人解析所需字段。
2. `QualityTaskService.list()` 增加 `selectTaskListColumns(...)`，只选择质量任务列表展示所需字段。
3. `QualityTaskService.listOnline()` 复用 `selectTaskListColumns(...)`，工作流候选列表不再读取任务 SQL、参数绑定和规则快照。
4. 保留详情、编辑、发布计算、规则 options 的完整读取路径，不删除下钻页面真实需要的数据。
5. 新增 `QualityListSourceSlimmingRegressionTest`，用 MyBatis-Plus wrapper 的 `sqlSelect` 直接断言源头列选择，防止再次出现“响应轻、源头重”。

## 是否需要修复

需要，已修复。原因是三个接口均属于列表/候选接口，虽然响应体已经轻量，但源头仍读取详情字段，违反“源头上就轻，杜绝表面轻、内里重”的约定。

## 剩余风险

1. `GET /quality-rules/options` 当前仍返回完整 `QualityRuleView`，任务编辑页会使用规则输入输出参数和 SQL 详情，暂不收敛；后续若出现大规模规则选项性能问题，应新增专用轻量 options，而不是直接删字段。
2. 质量规则启停、质量任务发布已在 S26 改为单行 patch，本轮未重新执行写入类点击，后续模块细测可用网络请求断言补充验证。
