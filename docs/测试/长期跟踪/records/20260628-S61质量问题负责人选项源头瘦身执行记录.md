## 发现的问题

`/quality-metrics` 的“问题中心”和问题处置抽屉只需要负责人下拉：

- `userId`
- `username`
- `displayName`
- `label`

旧前端实现先调用系统管理项目成员列表：

- `GET /api/v1/system/project-members?projectId=2068077680446365698`

该接口是系统管理项目成员表格视图，返回 `createdAt/deleted/id/projectId/projectName/roleCode/status/tenantId/updatedAt/userId/username/displayName`。若该接口不可用，前端又后备调用全局用户管理列表：

- `GET /api/v1/users`

这两个接口都不是质量问题负责人下拉的专用轻量接口，且系统管理项目成员接口对非管理成员不友好。

## 本轮整改

1. 新增质量问题负责人选项接口
   - 新增 `QualityIssueAssigneeOptionView`。
   - 新增 `GET /api/v1/quality-metrics/assignee-options`。
   - `QualityIssueService.listAssigneeOptions()` 基于当前租户、当前项目查询项目成员。

2. 源头瘦身
   - 查询 `studio_project_member` 时只 select `user_id`。
   - 查询 `sys_user` 时只 select `id/username/display_name`。
   - `resolveUserDisplayName()` 也改为只读取用户显示所需字段，不再 `selectById` 读取完整用户行。

3. 前端替换调用点
   - `QualityMetricsView.loadAssignees()` 改为只调用 `qualityMetrics.assigneeOptions()`。
   - 删除质量指标页对 `system.projectMembers.list()` 和 `users.list()` 的负责人加载依赖。
   - 本地仍保留去重和 label 兜底。
