## 发现的问题

`/quality-metrics/options` 首屏只用于全局筛选，但旧实现：

- 数据源筛选复用 `dataSourceService.listSummaries()`，触发连接健康状态和趋势水合，筛选只需要 `id/name/typeCode/label`。
- 模型筛选通过 `listModelSummaries()` 循环调用模型表格摘要页，每页 5000 条，首屏拉取全部模型；筛选下拉实际应按打开/搜索分页加载。
- 质量指标计算上下文也复用带连接健康水合的数据源摘要，但后续只使用数据源名称和类型。

## 本轮整改

1. 数据源筛选轻量化
   - 新增 `DataSourceService.listMetricFilterOptions()`，源头只 select `id/name/typeCode`。
   - 新增 `DataSourceService.listBasicSummaries()`，质量指标计算上下文不再触发连接健康水合。

2. 模型筛选分页化
   - 新增 `DataModelService.listMetricFilterOptionPage(datasourceId, keyword, pageNo, pageSize)`。
   - 源头只 select `id/name/physicalLocator`，每页最多 100。
   - 新增 `GET /api/v1/quality-metrics/model-options`。

3. 前端加载收敛
   - `/quality-metrics/options` 初始只返回数据源筛选项，`models` 为空。
   - `QualityMetricsFilterSection` 的模型下拉改为远程搜索；打开下拉或输入关键字时请求 `/quality-metrics/model-options?pageNo=1&pageSize=50`。
   - 切换数据源时只清空当前模型筛选和模型选项缓存，不刷新整页 options。
   - 从资产详情进入问题详情时懒加载负责人候选，避免负责人下拉为空。
