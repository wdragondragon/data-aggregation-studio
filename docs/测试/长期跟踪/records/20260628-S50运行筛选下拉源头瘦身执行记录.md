# S50 运行筛选下拉源头瘦身执行记录

## 背景

- 日期：2026-06-28
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：继续结合页面和代码排查前端可达点中过度获取数据的接口，重点判断下拉/筛选控件是否复用表格列表接口。

## 发现的问题

1. 采集任务日志页 `/collection-task-runs`
   - 任务筛选下拉只展示 `name / projectId`，提交 `id`。
   - 前端调用 `GET /collection-tasks`，返回表格视图字段：`taskType/status/sourceCount/targetDatasourceName/targetModelName/schedule` 等。
   - 后端源头为表格列表额外查询并组装采集任务 schedule。

2. 工作流日志页 `/runs`
   - 工作流筛选下拉只展示 `name / projectId`，提交 `id`。
   - 前端调用 `GET /workflows`，返回表格视图字段：`code/versionId/versionNumber/published/schedule` 等。
   - 后端源头为表格列表额外批量查询 workflow schedule。

这两个页面不需要表格列，也不需要 schedule，符合“应新增简单视图接口而不是复用列表接口”的整改条件。

## 本轮整改

1. 新增轻量 DTO
   - `CollectionTaskOptionView`：只返回 `id/projectId/name`。
   - `WorkflowOptionView`：只返回 `id/projectId/name`。

2. 新增轻量接口
   - `GET /api/v1/collection-tasks/options`
   - `GET /api/v1/workflows/options`

3. 源头查询约束
   - 采集任务 option 查询只 select `id/project_id/name`，不读取 `task_type/status/source_count/target_*/*_json`，不查询 schedule。
   - 工作流 option 查询只 select `id/project_id/name`，不读取 `code/current_version_id/published/created_by`，不查询 schedule。

4. 前端调用调整
   - `/collection-task-runs` 的任务筛选下拉改用 `studioApi.collectionTasks.options()`。
   - `/runs` 的工作流筛选下拉改用 `studioApi.workflows.options()`。
