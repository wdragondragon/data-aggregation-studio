## 发现并修复的问题

### BUG-S14-001 协议转换调试/Trace 中 Query/Form 敏感字段未脱敏

- 严重级别：高。
- 复现批次：`20260622-S14-VERIFY`，最终回归批次 `20260622010840`。
- 复现步骤：
  1. 登录长期项目后调用 `POST /api/v1/protocol-conversions/2068145027555180546/debug`。
  2. 请求中传入 Header `X-S14-Secret-Token`、Query `api_key`、Form `clientSecret`、Body `password/clientSecret/api_key`。
  3. 查看 debug 返回的 `conversionTrace.sourceRequest`。
- 修复前实际：
  - Header `X-S14-Secret-Token` 已遮蔽。
  - Body `password` 已遮蔽。
  - Query `api_key` 和 Form `clientSecret` 以原文返回给前端。
- 影响范围：
  - 协议转换 debug 接口返回。
  - 协议转换四阶段 Trace 的 `sourceRequest.query/form`。
  - debug 结果中的 `targetRequest` 快照如目标 URL/body 带敏感字段，也存在诊断输出泄漏风险。
- 根因：
  - `ProtocolConversionService#sourceRequestTraceStep` 对 Header 使用 `sanitizeHeaders`，但 Query/Form 直接使用 `safeMap`。
  - `sanitizeTargetRequest` 仅遮蔽 headers，body 只截断不脱敏，url query 未按敏感参数名遮蔽。
- 修复：
  - 新增诊断输出专用脱敏路径 `sanitizeSensitiveMap`、`sanitizeSensitiveList`、`sanitizeUrl`、`sanitizeSensitiveText`。
  - `sourceRequestTraceStep` 对 Query/Form 使用敏感字段名脱敏。
  - `previewForTrace` 的 fallback 也走 `OpenServiceInvocationLogSupport.sanitizeSensitiveLog`。
  - `sanitizeTargetRequest` 对 URL、body、嵌套 map 和字符串值做诊断脱敏。
  - 不改变协议转换实际转发请求，只改变 debug/Trace/日志展示结构。
- 修复文件：
  - `backend/studio-infra/src/main/java/com/jdragon/studio/infra/service/ProtocolConversionService.java`
  - `backend/studio-test/src/test/java/com/jdragon/studio/infra/service/WebServiceSupportTest.java`
- 回归测试：
  - 新增 `shouldMaskSensitiveProtocolConversionTraceDiagnostics`，覆盖 source Trace 的 Header/Query/Form/Body 和 debug targetRequest 的 URL/Header/Body。
