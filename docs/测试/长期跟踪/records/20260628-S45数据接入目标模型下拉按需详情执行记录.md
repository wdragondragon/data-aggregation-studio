- 测试账号：`admin/admin123`
- 数据策略：长期测试数据不清理；本轮未新增业务数据，复用长期 MySQL8 数据源和模型。

## 本轮发现

1. `/data-ingestion-services/new` 的“模型”下拉原先调用 `studioApi.models.listByDatasource(...)`，即 `GET /models/datasource/{datasourceId}`。
2. 该完整模型接口会返回每个模型的 `technicalMetadata/businessMetadata`，长期项目主 MySQL8 数据源当前 31 个模型，第一页 20 条完整列表约 26.1KB，并包含字段元数据。
3. 页面下拉选项只展示 `name / physicalLocator`，不需要完整模型定义。
4. 但同页 Writer 主键默认值和字段映射选项需要选中模型的 `technicalMetadata.columns`，因此不能直接删除完整模型能力；应改为“下拉摘要列表 + 选中模型详情按 id 获取”。

## 修复内容

1. `DataIngestionServiceEditorView.vue` 中 `models` 改为 `DataModelListView[]`。
2. 数据源切换后模型下拉改用 `studioApi.models.listSummariesByDatasource(...)`，即 `GET /models/datasource/{datasourceId}/summaries`。
3. 新增模型详情缓存 `modelDetailCache`，只在编辑页回显或用户选择模型时调用 `studioApi.models.get(modelId)`。
4. `targetModel` 改为从详情缓存读取，保留 `resolveFieldsByModel(...)` 和 `resolvePrimaryKeyFieldsByModel(...)` 的字段元数据能力。
5. 当选中模型正在加载详情时，`解析目标字段` 按钮显示加载态，避免字段详情未加载完成时误操作。

## 是否需要修复

需要，已修复。原因是数据接入服务目标模型下拉属于选项列表视图，已有按模型 id 的详情接口；页面不应在选择数据源时批量获取所有模型的完整元数据。

## 剩余风险

1. 采集任务、质量任务、数据开发等页面仍存在完整模型列表调用，但这些页面当前直接使用 `technicalMetadata.columns` 构建字段/SQL 提示，不能简单替换为摘要接口；后续应逐页设计“摘要列表 + 按需详情/字段提示接口”。
2. 本轮只改接入服务编辑页的模型下拉过取，不改变后端完整模型接口契约。
