## 本轮确认问题

1. 元模型中心 `/metadata`
   - 页面首屏 `loadPage()` 调用 `studioApi.metaSchemas.list()`，后端默认 `includeFields=true`。
   - 树目录与右侧基础详情只需要 `id/schemaCode/schemaName/objectType/typeCode/currentVersionId/status/description/versionNumber` 等摘要字段，但首屏会返回所有元模型的 `fields`。
   - 预览与编辑确实需要字段定义，但它们属于选中叶子节点的下钻数据，应按 schema id 获取。
   - 保存草稿、发布、删除、同步单类、同步全部后均调用 `loadPage()`，导致一次变更刷新元模型列表、所有字段和数据源类型。
   - 判定：真实存在首屏字段过取与变更后刷新范围过大的问题。

2. 统计分析中心 `/statistics`
   - `DataModelStatisticsWorkspaceService.options()` 调用 `metadataSchemaService.listSchemas()` 获取全量字段，用于筛选统计 query/target schema。
   - `resolveAvailableModelMetaModelCodes()` 再次调用 `listSchemas()`，但只需要 schema 摘要字段，不需要任何字段定义。
   - 统计选项返回字段是页面必需数据，但应先用轻量 schema 摘要筛选候选，再只对候选 schema 批量加载字段。
   - 判定：真实存在统计选项源头重复全量字段加载问题。

## 本轮整改

1. 元模型后端能力
   - `GET /api/v1/meta-schemas` 保留默认 `includeFields=true`，兼容现有依赖。
   - 新增 `GET /api/v1/meta-schemas/{schemaId}`，用于按 id 获取单个元模型详情和字段定义。
   - `MetadataSchemaService` 新增 `getSchema(schemaId)` 与 `listSchemasWithFieldsByIds(schemaIds)`，后者用于候选 schema 的批量字段加载。

2. 元模型前端局部刷新
   - `/metadata` 首屏改为 `studioApi.metaSchemas.list({ includeFields: false })`。
   - 选中叶子节点或编辑时调用 `studioApi.metaSchemas.get(id)`，字段定义进入详情缓存，预览区使用当前详情缓存。
   - 保存、发布、删除、同步操作不再整页 `loadPage()`；改为合并返回的受影响 schema 摘要、更新详情缓存、重新定位当前节点。
   - 手动点击刷新仍保留全页轻量刷新能力，并清空详情缓存后按当前选中节点重新获取单个详情。

3. 统计选项源头瘦身
   - `options()` 先调用 `metadataSchemaService.listSchemas(false)` 获取不含字段的 schema 摘要。
   - `resolveAvailableModelMetaModelCodes()` 改为复用摘要列表，不再第二次全量加载字段。
   - 根据摘要判断 query/target 相关候选 schema id，再用 `listSchemasWithFieldsByIds(...)` 一次性加载候选字段。
   - 保持前端统计选项返回结构不变，页面仍能直接渲染 querySchemas/targetSchemas/fields。
