## 发现的问题

运行指标页通过以下接口加载筛选项和趋势/TopN 指标：

- `GET /api/v1/run-metrics/options`
- `POST /api/v1/run-metrics/query`

代码复核确认：

- 页面筛选和 TopN 只需要采集任务绑定中的源/目标数据源、模型 ID、名称、类型和物理表名。
- 修复前 `RunMetricsService` 调用 `CollectionTaskService.listMetricBindings()`。
- `listMetricBindings()` 从 `collection_task_definition` 选择 `source_bindings_json`、`target_binding_json`，再反序列化为轻量视图。

该实现虽然响应数据较轻，但源头仍读取采集任务详情 JSON，违反“从源头上就轻，不获取完整数据再组合轻视图”的约定。

## 本轮整改

1. 新增轻量绑定快照表
   - 表：`collection_task_metric_binding`
   - 字段只保留运行指标筛选和 TopN 所需的任务、角色、数据源、模型摘要。
   - 不保存 `readerOptions/writerOptions/fieldMappings/executionOptions`。

2. 采集任务写入时同步维护快照
   - 保存采集任务后重建该任务的源/目标绑定快照。
   - 发布采集任务时只更新快照状态。
   - 删除采集任务时同步逻辑删除快照。

3. 运行指标改为源头轻量读取
   - `CollectionTaskService.listMetricBindings()` 改为只查 `collection_task_metric_binding`。
   - 不再读取 `source_bindings_json`、`target_binding_json`、`field_mappings_json`、`execution_options_json`。

4. schema 与升级补齐
   - `schema-mysql.sql`、`schema-sqlite.sql` 增加新表。
   - `StudioSchemaUpgradeService` 增加 MySQL/SQLite 建表、索引和一次性回填。
   - 旧数据回填只发生在 schema upgrade 阶段，运行期接口不依赖大 JSON。
