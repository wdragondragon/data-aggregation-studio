## 缺陷记录

| 编号 | 级别 | 问题 | 影响 | 根因 | 状态 |
|---|---|---|---|---|---|
| BUG-S09-001 | 中 | 采集任务失败运行记录暴露 Java 异常类、内部类名、源码文件名和堆栈；修复前历史记录在列表/API 中也继续暴露 | 用户无法获得干净可理解的结构变更失败原因，同时泄露内部实现细节；历史长期数据不清理时页面仍可见旧泄露信息 | `AggregationNodeExecutor` 将底层 `Throwable.getMessage()` 放入 payload，`ExecutionEventService` 入库时直接使用 `payload.error/message`；`RunService` 读路径又直接返回历史 `message/payloadJson/resultJson` | 已修复并回归通过 |

## 修复摘要

- 新增 `RunRecordMessageSanitizer`，统一处理运行记录错误消息：
  - 提取最底层 `Caused by` 根因。
  - 去除 Java 异常类前缀、堆栈帧、源码文件位置。
  - 保留数据库业务根因，例如 `Unknown column...`、`Field ... doesn't have a default value`。
  - 对 `payloadJson/resultJson` 中的 `message/error/errorMessage/logErrorSummary` 同步清洗，`exceptionType` 仅保留简单类名。
- `ExecutionEventService` 在写入运行记录时清洗 message、payload、result。
- `RunService` 在列表、详情和历史 fallback 日志输出时清洗旧历史数据，保留长期数据库原始记录但不继续向页面/API 暴露内部堆栈。
- `WorkflowRunService` 节点运行详情消息同步使用清洗后的运行记录消息。
- 修正 S09 探针中 `date_format` 证据字段，后续 `signed_at` 输出真实时间。
