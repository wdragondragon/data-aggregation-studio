## 本轮发现

1. `/quality-metrics` 的“问题中心”表格使用 `studioApi.qualityMetrics.queryIssues(...)` 调用旧 `POST /quality-metrics/issues/query`，后端一次返回全部问题，再由前端 `useClientPagination` 做本地分页。
2. `QualityIssueService.query(...)` 虽然已经只选择列表需要的字段，不读取 `currentEvidenceJson` 等详情字段，但仍使用 `selectList` 全量读取后在 Java 内存中排序和返回，分页没有下推到数据库。
3. 问题详情已有 `GET /quality-metrics/issues/{id}` 下钻接口，详情中的 `currentEvidence` 和时间线不应由表格接口承担。
4. 旧 `/quality-metrics/issues/query` 可能仍有兼容调用价值，因此不直接破坏旧契约，而是新增分页接口给表格页面使用。

## 修复内容

1. `QualityIssueQueryRequest` 增加 `pageNo/pageSize`。
2. 新增 `POST /quality-metrics/issues/page`，返回通用 `PageView<QualityIssueView>`。
3. `QualityIssueService.queryPage(...)` 使用 MyBatis-Plus `selectPage`，在源头只读取问题列表列，不读取 `currentEvidenceJson`、评论、事件时间线等详情数据。
4. 问题列表排序下推到数据库：活跃状态优先、严重级别优先、SLA 超时优先、最近出现时间倒序、id 倒序。
5. 旧 `query(...)` 保留兼容返回 `List<QualityIssueView>`，内部按页累积，不再保留单次 `selectList` 全量读取路径。
6. 前端 `QualityMetricsView.vue` 的“问题中心”切换为 `queryIssuesPage(...)`；页码和页大小变化只刷新当前问题页。
7. 问题处置后的列表刷新继续保持局部 patch：匹配当前筛选则替换当前行，不匹配则从当前页移除并扣减总数，不重拉整个质量指标页面。

## 是否需要修复

需要，已修复。原因是“问题中心”是表格视图，已有按问题 id 下钻详情接口；主表不应一次读取并返回全部问题再由前端分页。

## 剩余风险

1. `/quality-metrics` 的“资产洞察”仍是聚合型资产风险视图，当前实现需要质量任务、运行记录、问题集合共同计算风险和覆盖率；不能简单改成“后端全量聚合后切片”冒充源头分页，后续需要单独设计资产风险快照或数据库聚合模型。
2. `QualityMetricsService.buildContext(...)` 为仪表盘和资产洞察仍会加载一定范围内的运行记录、问题和事件，当前只处理本轮确认的“问题中心表格全量返回”问题。
