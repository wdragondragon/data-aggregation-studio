## 问题确认

| 编号 | 模块 | 现象 | 真实存在 | 是否需要修复 |
|---|---|---|---|---|
| S87-DD-001 | 数据开发/脚本执行 | `DataDevelopmentWorkerExecutionService.waitForCompletion()` 轮询时使用 `selectById` 读取 `dispatch_task.payload_json` 和 `run_record.payload_json/result_json/log_*` 等大字段 | 是 | 是 |
| S87-DD-002 | 数据开发/执行日志 | Java/Python 保存脚本执行完成后，结果区只需要日志预览，却立即调用完整下载接口 `/runs/{id}/log/download` | 是 | 是 |

根因：

- 执行结果最终需要 `payloadJson/resultJson`，但非终态轮询只需要 `id/status/runRecordId`；旧实现没有区分状态轮询与终态结果读取。
- 运行记录在执行结果区只需要 `logStatus/message/startedAt/endedAt`，常规路径无须读取 `payload_json/result_json/log_file_path/log_object_key`。
- 前端 `loadExecutionRunLog()` 直接调用 `studioApi.runs.downloadLog()`，完整下载更适合用户明确点击下载，不适合执行按钮的即时反馈。
