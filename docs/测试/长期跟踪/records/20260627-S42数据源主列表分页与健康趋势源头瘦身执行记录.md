## 本轮发现

1. `/datasources` 主列表由 `DatasourcesView.vue` 一次拉取全部数据源后使用前端分页；长期测试数据持续累积后会拖慢首屏。
2. 后端 `/datasources` 虽返回 `DataSourceListView`，但源头会先把摘要实体转换成完整 `DataSourceDefinition`，再裁剪成列表视图，存在“表面轻、内里重”的问题。
3. 数据源健康趋势补全会读取完整连接测试历史行，列表实际只需要 `tenant_id`、`connection_fingerprint`、`connection_status`、`ended_at`。
4. 数据源编辑、连接历史、表发现等下钻入口已有按 id 或专用接口，主表不需要承担技术元数据、业务元数据、连接配置等详情数据。

## 修复内容

1. 新增 `GET /datasources/page`，返回 `PageView<DataSourceListView>`，用于主列表服务端分页。
2. `DataSourceService.listSummaryPage(...)` 从源头只选择数据源摘要列，不读取 `technical_metadata`、`business_metadata` 等详情字段。
3. `DataSourceService.listSummaries()` 兼容旧入口，但复用轻量摘要查询和直接实体到列表视图的转换，不再先组装完整定义。
4. `DatasourceConnectionHealthService.hydrateListViews(...)` 专用于列表健康状态补全，健康趋势查询只读取列表需要字段。
5. `DatasourcesView.vue` 主表从前端分页改为服务端分页；删除后只刷新当前页，保存后优先局部 patch 当前行。
6. 新增 `DataSourceListSourceSlimmingRegressionTest`，断言分页列表、旧摘要列表和健康趋势 SQL 均不会读取完整元数据或完整连接历史行。

## 是否需要修复

需要，已修复。原因是数据源主列表属于表格视图，已有详情和操作下钻接口；主表不应全量拉取后前端分页，也不应通过完整定义或完整连接历史行组装轻量视图。

## 剩余风险

1. 旧 `/datasources` 为兼容入口仍返回全量摘要列表，但源头已经改为轻量摘要查询；主表已切换 `/datasources/page`。
2. 编辑抽屉、连接历史和发现表仍会按操作需要加载详情或历史数据，这是符合下钻按需获取的行为。
