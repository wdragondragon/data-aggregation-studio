- 长期项目：`长期回归测试项目` / `2068077680446365698`
- 测试账号：`admin/admin123`
- 数据策略：长期测试数据不清理；本轮未保存任何业务对象，复用长期 MySQL8 数据源和模型。

## 本轮发现

1. `/data-services/new` 的“数据表”模型下拉原先调用 `studioApi.models.listByDatasourcePage(...)`，即 `GET /models/datasource/{datasourceId}`。
2. 该完整模型接口会返回每个模型的 `technicalMetadata/businessMetadata`。长期项目主 MySQL8 数据源当前 31 个模型，完整列表约 45.1KB，并包含技术/业务元数据。
3. 数据服务编辑页的模型下拉只展示 `name / physicalLocator` 并提交 `modelId`；字段解析由 `studioApi.dataServices.resolveFields(...)` 按 `modelId` 在后端完成。
4. 因此页面不需要在选择数据源时批量读取所有模型的完整元数据，属于真实过取。

## 修复内容

1. `DataServiceEditorView.vue` 中 `models` 类型由 `DataModelDefinition[]` 改为 `DataModelListView[]`。
2. `loadModels(...)` 改为调用 `studioApi.models.listSummaryByDatasourcePage(...)`，即 `GET /models/datasource/{datasourceId}/summaries`。
3. 保留字段解析接口和完整模型详情接口契约，不影响数据服务按模型生成请求/返回字段。

## 是否需要修复

需要，已修复。原因是数据服务编辑页的模型下拉属于选项列表，字段元数据由后端解析接口按选中模型处理；下拉不应批量加载完整模型定义。

## 剩余风险

1. 数据开发 SQL 提示、采集任务编辑、质量任务编辑仍有完整模型列表调用，但这些页面当前会直接使用字段列元数据；后续需要逐页设计专用字段提示或按需模型详情缓存，不能直接替换。
2. 本轮只改数据服务编辑页的模型下拉，不改变后端完整模型接口契约。
