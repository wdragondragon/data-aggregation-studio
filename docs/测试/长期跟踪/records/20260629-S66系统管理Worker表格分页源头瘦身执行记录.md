## 发现的问题

系统管理 Worker tab 的表格数据源仍调用旧接口：

- `GET /api/v1/system/project-workers?projectId=...`

该接口会读取当前租户可见 Worker lease 全量记录和当前项目 Worker 绑定全量记录，再在 Java 中按 Worker 组聚合。表格实际只展示当前页 Worker 组，但旧实现会先取全量组及实例。

注意：旧全量接口不能直接删除或简单瘦身。绑定 Worker 组弹窗仍需要跨当前页提供候选 Worker 组，因此保留旧接口作为弹窗候选项来源；新增表格专用分页轻接口承载 Worker 表格视图。

## 本轮整改

1. 后端新增 Worker 表格分页源头查询
   - `WorkerLeaseMapper` 新增 Worker 组可见范围计数、Worker 组分页、当前页 Worker 组 lease 查询。
   - `ProjectWorkerBindingMapper` 新增按 Worker 组查询绑定关系。
   - `SystemManagementService` 新增 `listProjectWorkersPage(projectId, pageNo, pageSize)`，先分页 Worker 组，再只加载当前页组的 lease 和 binding。
   - `SystemManagementController` 新增 `GET /api/v1/system/project-workers/page`。

2. 前端 Worker 表格改为分页接口
   - `SystemView.vue` 将 Worker tab 纳入系统管理分页状态。
   - `loadProjectWorkers()` 改走 `system.projectWorkers.listPage(...)`。
   - 写操作后只刷新当前 Worker 表格页。
   - 绑定弹窗通过 `loadWorkerGroupsForDialog()` 懒加载旧全量接口，并与表格分页数据分离。

3. SDK 补充
   - `frontend/packages/api-sdk/src/client.ts` 新增 `system.projectWorkers.listPage(params, config)`。
