## 本轮发现

1. `/collection-tasks` 在 S25 后响应已是轻量列表视图，但后端源头仍读取 `source_bindings_json`、`target_binding_json`、`field_mappings_json`、`execution_options_json` 等采集任务详情配置。
2. 列表页需要展示目标数据源和目标模型字段，但这些字段只存在于 `target_binding_json`，导致“响应轻、源头重”。
3. `CollectionTasksView.vue` 对采集任务主表使用前端分页，进入页面会拉取当前项目全部采集任务，不符合表格页快速展示约定。
4. 列表组装时按任务逐条查询调度配置，存在 schedule N+1 查询风险。
5. 编辑、详情、发布、执行链路仍需要完整绑定配置，因此不适合直接裁剪原有详情读取能力；应为列表页提供真正轻量的分页接口。

## 修复内容

1. `collection_task_definition` 增加目标快照列：`target_datasource_name_snapshot`、`target_datasource_type_code_snapshot`、`target_model_name_snapshot`、`target_model_physical_locator_snapshot`。
2. `CollectionTaskService.save(...)` 在保存采集任务时从目标绑定写入快照字段；`StudioSchemaUpgradeService` 在启动升级时为历史任务回填快照。
3. 新增 `GET /collection-tasks/page`，服务层从源头只选择列表展示、筛选、权限、调度关联所需字段，不再读取四类详情 JSON。
4. 采集任务在线候选列表复用轻量字段选择，并批量查询调度摘要，避免逐行 `selectOne`。
5. `CollectionTasksView.vue` 主表切换为服务端分页，搜索和分页变更只刷新当前页；保留原 `/collection-tasks` 兼容入口给旧调用方和候选场景使用。
6. 新增 `CollectionTaskListSourceSlimmingRegressionTest`，断言分页和在线列表源头 select 字段、调度批量查询字段，以及不再调用逐行 schedule 查询。

## 是否需要修复

需要，已修复。原因是采集任务列表属于表格视图，目标展示字段可通过快照列满足，源头不应读取采集详情 JSON；主列表也不应一次拉取全部数据后前端分页。

## 剩余风险

1. 旧 `GET /collection-tasks` 为兼容旧调用方仍会按页循环读取摘要；主列表已切换到 `/collection-tasks/page`，后续若发现旧入口被大流量页面继续使用，应继续替换为分页或专用候选接口。
2. 历史数据快照依赖服务重启时 schema upgrade 回填；运行时验证需确认长期库已执行升级。
3. 本次提交前未单独补实服 nginx API 与页面截图记录，后续 S41 可优先复核 `/collection-tasks/page`、`/collection-tasks/online` 和 `/collection-tasks` 主页面。
