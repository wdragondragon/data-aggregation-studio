- 长期项目：`长期回归测试项目` / `2068077680446365698`
- 测试账号：`admin/admin123`
- 测试原则：长期测试数据不清理，本轮只验证页面首屏取数和下钻字段按需加载。

## 本轮发现

1. `/models` 和 `/datasources` 首屏仍调用默认 `GET /meta-schemas`。
2. 当前测试环境默认元模型列表约 284,926 字符，82 个 schema，包含 616 个字段定义。
3. 同一接口加 `includeFields=false` 后约 53,355 字符，82 个 schema，字段数为 0。
4. 两个页面首屏只需要 schema 摘要判断可选类型；编辑、表单默认值、字段渲染才需要具体 schema 字段，符合“列表/首屏轻，下钻按 id 获取详情”的整改条件。

## 修复内容

1. `MetaSchemaController` 新增 `GET /api/v1/meta-schemas/details?schemaIds=...`，按 id 批量返回含字段详情。
2. SDK 新增 `metaSchemas.details(schemaIds)`。
3. `/datasources` 首屏改为 `metaSchemas.list({ includeFields:false })`，打开编辑或切换数据源类型时再拉取当前类型相关 schema 详情。
4. `/models` 首屏改为 `metaSchemas.list({ includeFields:false })`，选择数据源、创建/编辑模型、进入详情编辑时再拉取相关模型 schema 详情。
5. 数据源删除后改为局部移除当前行，不再整页 `loadPage()`。
