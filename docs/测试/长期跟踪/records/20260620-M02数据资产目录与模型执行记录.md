## 修复记录

### BUG-M02-001 同步失败任务没有暴露数据库根因

现象：

- 使用错误密码数据源执行模型同步失败时，旧任务详情只显示类似 `Failed to load model metadata...`，不能直接看到 MySQL 根因。

修复：

- `backend/studio-infra/src/main/java/com/jdragon/studio/infra/service/execution/AggregationSourceCapabilityProvider.java`
- 增加最深层异常提取，并解包 `InvocationTargetException`，失败明细优先返回底层 cause message。

验证：

- 新失败任务 `2068095081875496961` 详情页显示：
  `Failed to initialize pool: Access denied for user 'root'@'119.136.134.153' (using password: YES)`。
- 回归测试 `AggregationSourceCapabilityProviderRegressionTest` 通过。

### BUG-M02-002 同步失败项耗时不等于实际开始/结束时间

现象：

- 失败同步项内部结果曾显示约 `2 ms`，但 startedAt/finishedAt 跨度约 4-5 秒。

修复：

- `backend/studio-infra/src/main/java/com/jdragon/studio/infra/service/ModelSyncTaskService.java`
- `processSingleItem` 的 `durationMs` 改为按同步项 `startedAt` 到 `finishedAt` 计算。

验证：

- 重启 StudioServer 后创建失败任务 `2068095081875496961`。
- 任务详情页显示任务持续时间 `5.17 s`，逐表明细耗时 `4.19 s`，与接口 startedAt/finishedAt 一致。
- 回归测试 `ModelSyncTaskServiceRegressionTest` 通过。

### 改进-M02-003 元模型列表轻量字段参数

改动：

- `MetaSchemaController` 支持 `includeFields` 参数。
- `MetadataSchemaService` 支持批量装载 schema/version/field，避免列表逐条查版本和字段。
- `frontend/packages/api-sdk/src/client.ts` 增加 `metaSchemas.list({ includeFields })` 参数。

验证：

- `/api/v1/meta-schemas?includeFields=false` 返回 76 个 schema，字段数组为空。
- `/api/v1/meta-schemas?includeFields=true` 返回 76 个 schema，包含字段定义。
- `/metadata` 页面加载、业务树、动态表单预览正常。
