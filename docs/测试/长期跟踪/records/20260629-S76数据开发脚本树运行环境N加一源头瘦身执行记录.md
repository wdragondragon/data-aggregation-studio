# S76 数据开发脚本树运行环境 N+1 源头瘦身执行记录

## 背景

- 日期：2026-06-29
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：继续深挖数据开发页面是否存在“表格/树视图展示轻，但源头逐行读取下钻详情”的过度取数问题。

## 发现的问题

涉及页面：
- `/data-development`

涉及接口：
- `GET /api/v1/data-development/tree`
- `GET /api/v1/data-development/scripts`

代码复核确认：
1. 数据开发脚本树和脚本列表只需要展示脚本基础字段、数据源名称和 Java 脚本运行环境名称。
2. 修复前 `DataDevelopmentService#buildTree` 和 `listScripts` 在遍历 Java 脚本节点时逐个调用 `safeResolveEnvironment(...)`。
3. `safeResolveEnvironment(...)` 会调用 `ScriptEnvironmentService#requireEnabledEnvironment(...)`，按运行环境 ID 读取单个完整运行环境实体。
4. 当数据开发目录下存在大量 Java 脚本时，首屏脚本树和列表会形成运行环境 N+1 查询；并且树/列表视图不需要运行环境详情字段，违反“表格/树视图从源头轻量获取”的约定。

## 本轮整改

1. 数据开发脚本树和列表批量解析运行环境
   - `DataDevelopmentService#tree()` 先收集当前脚本集合里的 Java 运行环境 ID。
   - `DataDevelopmentService#listScripts()` 复用同一批量解析逻辑。
   - 保留单个脚本详情路径继续按需调用完整运行环境解析。

2. 新增运行环境轻量批量接口
   - `ScriptEnvironmentService#enabledOptionMapByIds(Set<Long>)`
   - 源查询只选择选项展示所需字段：
     - `id`
     - `tenant_id`
     - `deleted`
     - `created_at`
     - `updated_at`
     - `environment_name`
     - `environment_code`
     - `enabled`
   - 不读取 `description`、`use_application_parent`、`environment_version` 等详情字段。

3. 增加回归测试
   - `DataDevelopmentSourceSlimmingRegressionTest`
   - `ScriptEnvironmentOptionsSourceSlimmingRegressionTest`
   - 断言脚本树和脚本列表批量解析 Java 运行环境名称，不调用 `requireEnabledEnvironment(...)`。
