# S37 工作流运行列表源头瘦身执行记录

## 背景

- 日期：2026-06-27
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 后端服务：IDEA `StudioServerApplication`，环境变量 `NACOS_SERVER=127.0.0.1:8848`
- 数据策略：未新增、未清理长期测试数据。

## 本轮发现

1. `/runs` 页面使用 `GET /workflow-runs?pageNo=1&pageSize=20` 展示工作流运行表格。实测长期项目响应约 10KB，响应体不包含 `payloadJson/resultJson/logObjectKey/logFilePath/nodeRuns/workflow`，表面返回已轻量。
2. 代码侧确认 `WorkflowRunService.list()` 和状态筛选分支仍用 MyBatis-Plus 整行读取 `run_record`、`dispatch_task`：
   - `run_record` 会读取 `payloadJson/resultJson/logFilePath/logObjectKey` 等列表不需要的大字段。
   - `dispatch_task` 会读取 `payloadJson`。
3. 摘要组装还会调用 `workflowService.get()`，为了节点名、节点类型和节点总数读取完整工作流详情，包括节点 `configJson/fieldMappingsJson`。这些字段只属于详情/DAG 编辑下钻数据，不应由运行列表预载。
4. 判定：真实存在“表面响应轻、源头查询重”的问题，需要修复。

## 修复内容

1. `WorkflowRunService` 新增运行摘要专用查询：
   - `summaryRunRecordQuery(...)` 只选择运行列表和节点摘要需要的运行 ID、工作流 ID、版本 ID、节点 code、状态、worker、消息、起止时间等字段。
   - `summaryDispatchTaskQuery(...)` 只选择调度状态、worker、节点和工作流引用字段。
2. 工作流名称查询从源头只选择 `id/name`。
3. 新增工作流节点元数据批量查询，只选择 `workflowVersionId/nodeCode/nodeName/nodeType`，不读取 `configJson/fieldMappingsJson`。
4. 运行列表和状态筛选摘要不再调用 `workflowService.get()`；工作流运行详情 `/workflow-runs/{id}` 仍保留按 id 获取完整工作流详情，用于 DAG 展示和节点详情。
5. 新增 `WorkflowRunSourceSlimmingRegressionTest`，断言摘要列表源头查询不选择运行 JSON、日志归档字段、调度 payload 和节点配置/字段映射。

## 是否需要修复

需要，已修复。原因是工作流运行列表虽未把大字段返回给前端，但后端源头仍读取运行 JSON、日志归档字段和完整工作流节点配置，违反当前 Studio 的“从源头轻量，不做表面轻”约定。

## 剩余风险

1. 运行详情页仍按 id 读取完整工作流详情，这是 DAG 下钻展示所需数据，本轮不做瘦身。
2. 状态筛选目前仍需要按候选运行批量构建摘要后过滤，已收敛每批源头字段；后续如长期项目运行量继续增长，可考虑增加独立工作流运行摘要物化表或 SQL 聚合视图。
