# S54 工作流数据脚本选择重复批量取数执行记录

## 背景

- 日期：2026-06-28
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：继续结合页面和代码排查前端可达点中过度获取数据的接口，重点验证工作流编辑器的数据脚本节点选择链路。

## 发现的问题

`/workflows/new` 工作流编辑页的数据脚本节点存在重复批量取数：

- 选中 `DATA_SCRIPT` 节点时，watcher 调用 `ensureScriptsLoaded()`。
- 打开脚本选择弹窗时，`openScriptDialog()` 同时调用 `ensureScriptsLoaded()` 和 `ensureScriptTreeLoaded()`。
- `ensureScriptsLoaded()` 调用 `studioApi.dataDevelopment.listScripts()`，即 `GET /data-development/scripts`。

但页面实际用途为：

- 脚本选择弹窗左侧目录树使用 `GET /data-development/tree`，tree 已提供 `scriptId/name/scriptType/datasourceName/environmentName` 等展示字段。
- 右侧预览和最终绑定需要脚本内容、数据源 ID 等详情字段，应按选中脚本调用 `GET /data-development/scripts/{id}`。
- 旧 `GET /data-development/scripts` 是数据开发列表/管理场景可保留的批量列表接口，不应在工作流选择弹窗中重复调用。

长期项目 nginx API 基线：

| 接口 | 响应大小 | 数量 | 字段摘要 |
|---|---:|---:|---|
| `GET /data-development/scripts` | 3066 bytes | 6 | `id/projectId/directoryId/fileName/scriptType/datasourceId/datasourceName/datasourceTypeCode/environmentId/environmentName/description`，无 `content` |
| `GET /data-development/tree` | 4077 bytes | 11 tree nodes / 6 script nodes | `nodeKey/nodeType/directoryId/scriptId/parentId/projectId/name/permissionCode/scriptType/datasourceName/environmentId/environmentName/children` |

判定：真实存在前端重复批量取数问题。旧批量接口适合保留给数据开发列表页使用，本轮只收敛工作流编辑器调用路径。

## 本轮整改

1. `WorkflowEditorView.vue`
   - 移除 `scriptsLoaded` 和 `ensureScriptsLoaded()`。
   - 选中 `DATA_SCRIPT` 节点时不再预取全量脚本列表。
   - 打开脚本选择弹窗时只加载 `GET /data-development/tree`。
   - 选中脚本后仍通过 `GET /data-development/scripts/{id}` 加载详情预览，并缓存已选脚本用于绑定。
   - 已保存工作流回显时，优先使用已缓存详情；没有缓存时用节点配置生成绑定摘要，避免为展示摘要拉取全量列表。
   - 绑定确认前若详情缓存缺失，则按选中脚本 ID 补一次详情请求，确保绑定配置仍包含 `datasourceId` 等下钻字段。

2. `WorkflowResourceDialogs.vue`
   - `confirmScriptSelection` action 类型调整为 `void | Promise<void>`，匹配确认前按需加载脚本详情的异步流程。
