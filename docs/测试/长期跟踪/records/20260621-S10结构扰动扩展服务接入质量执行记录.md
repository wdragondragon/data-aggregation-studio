## 发现与修复

### BUG-S10-001：质量任务字段改名失败记录的 stackTrace 继续暴露 Java 堆栈

- 复现批次：`20260621223638`
- 现象：质量任务因 `contract_amount` 字段改名失败后，`run_record.message` 已被清洗，但 `payloadJson.stackTrace` 和 `resultJson.stackTrace` 仍包含 `com.jdragon...`、`.java:`、完整 Java 调用栈。
- 影响：运行详情/API/日志链路读取 payload/result 时仍可能泄露内部实现和源码位置。
- 根因：`RunRecordMessageSanitizer` 递归处理 `message/error/errorMessage/logErrorSummary/exceptionType`，未将 `stackTrace` 当作错误文本清洗。
- 修复：将 `stackTrace` 纳入错误文本清洗键，并补充写入路径与历史读取路径测试。
- 回归：
  - `mvn -pl studio-test -am "-Dtest=ExecutionEventServiceRegressionTest,RunServiceRegressionTest" "-Dsurefire.failIfNoSpecifiedTests=false" "-DforkCount=0" test`：4 PASS。
  - 重启 `StudioServerApplication`、`StudioWorkerApplication` 后，S10 最终批次 `20260621225707`：9 PASS / 0 FAIL / 0 BLOCKED / needFix 0。
  - 浏览器复核 `/data-services/2068704693544779778/edit?debug=1`、`/data-ingestion-services/2068704728974065665/edit?debug=1`、`/quality-task-runs?qualityTaskId=2068704774037667842`：页面可达，forbidden marker 为空，console warn/error 为空。
