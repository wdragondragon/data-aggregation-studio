## 修复记录

### BUG-M06-001 增量 DATETIME 游标二次运行类型比较失败

现象：

- `长期回归-客户订单增量采集任务` 首次运行后，把最大游标保存为字符串，例如 `2026-06-20 10:06:00`。
- 再次运行时，读取到的 JDBC 列值为 `TimestampColumn`，和已保存的字符串游标比较时报错：`java.lang.RuntimeException: 不支持的类型对比`。
- 运行态失败记录：`2068153474438807553`。

根因：

- `CommonRdbmsReader` 对已持久化的增量游标没有按采样结果列类型做归一化。
- 字符串形式的 DATETIME 游标直接参与 `TimestampColumn` 比较，触发类型不兼容。

修复：

- 文件：`job-plugins/utils/plugin-rdbms-util/src/main/java/com/jdragon/aggregation/rdbms/reader/CommonRdbmsReader.java`
- 新增已保存游标类型归一化逻辑，使 JDBC date/datetime 字符串按采样列类型转为可比较列。
- 对 date、datetime、timestamp 字符串增加显式解析，避免再次落入不支持类型比较。

回归：

```powershell

结果：

  - 首次修复后运行 `2068159144173195265`：`SUCCESS`，游标为 `2026-06-20 10:06:00`。
  - 插入保留订单 `ORD-M06-FIX-20260620-002`。
  - 二次运行 `2068159206689296385`：`SUCCESS`，游标推进到 `2026-06-20 10:25:00`。

### BUG-M06-002 融合任务未把 join key 纳入每个源查询字段

现象：

- `长期回归-订单支付融合采集任务` 运行失败。
- 融合 reader 生成源查询时只选择显式映射字段，例如 `payment_amount,pay_method,pay_time`，但后续又按 `order_id` 做排序和 join。
- 运行时报错目标源不存在 `order_id`：`Unknown column 'order_id'`。
- 运行态失败记录：`2068153503173984257`。

根因：

- `CollectionTaskFieldMappingResolver` 构建融合任务字段列表时，只从显示映射中提取源字段。
- `CollectionTaskAssemblerService` 没有保证每个 source binding 都把 `joinKeys` 纳入 reader 查询字段。

修复：

- 文件：`data-aggregation-studio/backend/studio-infra/src/main/java/com/jdragon/studio/infra/service/CollectionTaskAssemblerService.java`
- 文件：`data-aggregation-studio/backend/studio-infra/src/main/java/com/jdragon/studio/infra/service/CollectionTaskFieldMappingResolver.java`
- 融合源字段现在会合并显式映射字段和 join key。
- 若某个源模型缺少 join key，保存/预览阶段抛出可读的 bad request，而不是运行期生成非法 SQL。

回归：

```
