- 执行时间：2026-06-27
- 前端入口：http://127.0.0.1:8000/dfs/data-aggregation-studio
- 后端服务：IDEA `StudioServerApplication`，`NACOS_SERVER=127.0.0.1:8848`
- 长期项目：`长期回归测试项目` / `2068077680446365698`
- 测试账号：`admin/admin123`
- 数据策略：长期测试数据不清理；本轮未新增业务数据。

## 本轮发现

1. `/collection-task-runs` 页面调用 `/runs` 展示采集运行列表，响应已经不返回 `payloadJson/resultJson/log*` 等大字段，但 `RunService.list()` 源头仍整行读取 `run_record`，包括 `payloadJson/resultJson/logObjectKey/logFilePath` 等详情/日志字段。
2. `/runs` 为了解析采集任务名称调用 `collectionTaskService.list(null, null, null)`，该路径会读取采集任务完整定义，包括 `sourceBindings/targetBinding/fieldMappings/executionOptions`。
3. `/runs` 为了解析质量任务名称调用 `qualityTaskService.list(null, null, null, null)`，该路径会读取质量任务完整定义，包括参数绑定、规则快照、SQL 预览等列表不需要的配置字段。
4. 队列列表查询 `dispatch_task` 未显式限制字段，会读取 `payloadJson`，但页面只展示队列摘要字段。

## 修复内容

1. `CollectionTaskService` 新增 `listAccessibleNames()`，源头只选择 `id/name`，用于运行列表名称映射。
2. `QualityTaskService` 新增 `listAccessibleNames()`，源头只选择 `id/taskName`，用于运行列表名称映射。
3. `RunService.list()` 的 `dispatch_task` 查询改为显式选择队列摘要字段，排除 `payloadJson`。
4. `RunService.list()` 的 `run_record` 查询改为显式选择列表摘要和指标列，排除 `payloadJson/resultJson/log*`。
5. 运行列表的 `durationMs` 改为从 `startedAt/endedAt` 计算；运行详情和日志下钻仍保留按 id 读取完整记录。

## 是否需要修复

需要，已修复。原因是 `/runs` 属于表格/列表接口，虽然响应体已经轻量，但源头仍读取运行详情 JSON、日志归档字段、采集任务完整配置和质量任务完整配置，违反“源头轻量，不允许表面轻、内里重”的约定。

## 剩余风险

1. `/collection-task-runs` 前端仍是客户端分页，长期运行记录继续增长后会有行数级过取风险；后续建议做服务端分页和状态统计聚合接口。
2. 采集任务主列表 `/collection-tasks` 已响应轻量，但仍存在客户端分页和 schedule 逐行查询，后续可作为单独专项继续收敛。
