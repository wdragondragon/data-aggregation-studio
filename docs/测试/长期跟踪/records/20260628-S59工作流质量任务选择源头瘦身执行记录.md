## 发现的问题

工作流编辑页的“选择质量任务”弹窗只用于绑定已上线质量任务。弹窗展示和绑定需要：

- `id`
- `projectId`
- `updatedAt`
- `taskName`
- `taskCode`
- `ruleId`
- `ruleName`
- `ruleDimension`
- `granularity`
- `datasourceId`
- `datasourceName`
- `modelId`
- `modelName`
- `columnName`

旧实现调用 `qualityTasks.listPage({ status: "ONLINE" })`，对应 `GET /api/v1/quality-tasks` 表格分页接口。该接口适合质量任务主列表保留，但弹窗不是主表格场景，实际额外返回并源头 select：

- `tenantId`
- `deleted`
- `createdAt`
- `createdBy`
- `status`
- `datasourceTypeCode`
- `modelPhysicalLocator`

这违反“表格接口只服务表格视图；下钻/选择场景如需要不同字段应新增轻量视图接口”的约定。

## 本轮整改

1. 保留旧表格接口
   - `/quality-tasks` 继续作为质量任务主表格分页接口。
   - `/quality-tasks/online` 和 `/quality-tasks/options` 保持兼容。

2. 新增工作流绑定候选接口
   - 新增 `QualityTaskWorkflowOptionView`。
   - 新增 `GET /api/v1/quality-tasks/workflow-options`。
   - `QualityTaskService.listWorkflowOptions(...)` 只查询当前租户、当前项目、`ONLINE` 状态质量任务。
   - 源头 select 仅包含工作流弹窗展示和绑定所需字段，不 select `status/createdBy/datasourceTypeCode/modelPhysicalLocator` 等表格字段，也不读取详情大字段。

3. 前端替换调用点
   - `WorkflowEditorView` 的质量任务弹窗改用 `qualityTasks.workflowOptions(...)`。
   - `WorkflowResourceDialogs` 和 `WorkflowSelectedNodePanel` 的质量任务类型改为 `QualityTaskWorkflowOptionView`。
   - 节点绑定仍写入原有工作流配置字段，保存工作流契约不变。
