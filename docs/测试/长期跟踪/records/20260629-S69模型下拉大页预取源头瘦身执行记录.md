# S69 模型下拉大页预取源头瘦身执行记录

## 背景

- 日期：2026-06-29
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：继续深挖编辑页下拉是否存在“只为选择模型却预取大页模型摘要”的过度获取问题。

## 发现的问题

以下编辑页在选择数据源后，会为模型下拉预取同数据源的大页模型摘要：

- `/collection-tasks/new`
- `/data-ingestion-services/new`
- `/data-services/new`
- `/quality-tasks/new`

前端调用路径包括：

- `studioApi.models.listSummariesByDatasource(... pageSize: 5000)`
- `studioApi.models.listSummaryByDatasourcePage(... pageSize: 500)`

这些下拉只需要展示 `id/name/physicalLocator/modelKind`，模型字段、SOAP 元数据、技术元数据等详情已经在选中模型后通过 `GET /models/{id}` 单独获取。继续复用 `/models/datasource/{datasourceId}/summaries` 会让大数据源下的编辑页在切换数据源时预取过多模型摘要，且承担了下钻详情之外的多余字段。

## 本轮整改

1. 新增数据源模型下拉专用视图
   - 新增 `DataModelDatasourceOptionView`。
   - 字段仅包含 `id/datasourceId/name/modelKind/physicalLocator`。

2. 新增源头轻量分页接口
   - 新增 `GET /api/v1/models/datasource/{datasourceId}/options`。
   - 支持 `keyword/pageNo/pageSize`。
   - 服务端将单页最大值收敛为 `100`。
   - SQL 源查询只选择下拉所需列，不读取 `schemaVersionId/technicalMetadata/businessMetadata`。

3. 前端编辑页改为远程轻量选项
   - 采集任务、数据接入、数据服务、质量任务模型下拉改用新 options 接口。
   - 选择数据源或打开下拉时只加载当前页选项。
   - 输入关键词时远程搜索模型名和物理表名。
   - 已选模型不在当前页时，通过已选模型详情补入当前下拉选项，不回退到全量预取。
