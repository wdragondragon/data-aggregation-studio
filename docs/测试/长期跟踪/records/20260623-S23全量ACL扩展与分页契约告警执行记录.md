## 真实缺陷

### BUG-S23-001 前端分页 PageResult 未统一规范化

- 级别：中。
- 影响范围：直接 `request<PageResult<...>>` 的前端 SDK 方法，包括字段映射规则、质量规则、数据服务、数据接入服务、协议转换、三类访问日志/指标、模型同步任务、运维中心、通知、工作流运行等。
- 复现步骤：
  1. 使用 `lt_reg_s01_receiver_member` 登录接收项目。
  2. 访问 `/protocol-conversions/access-logs`。
  3. 后端接口返回 `total:"0"` 字符串，Element Plus `el-pagination` 的 `total` prop 期望 number，触发 deprecated usage warning。
- 根因：
  - SDK 已有 `normalizePageResult`，可把 `total/pageNo/pageSize` 转为 number。
  - 多个分页方法直接调用 `request<PageResult<T>>`，绕过了该规范化函数。
- 修复文件：
  - `frontend/packages/api-sdk/src/client.ts`
- 修复摘要：
  - 新增 `requestPage<T>()`，统一在 SDK 层调用 `normalizePageResult`。
  - 将直接返回 `PageResult` 的分页接口改为 `requestPage`。
- 验证：
  - `npm run build:web`：通过。
  - API 证据：`/protocol-conversion-metrics/access-logs/query` 仍返回 `total:"0"`，证明前端必须兼容字符串 total。
  - Browser 证据：协议转换访问日志、数据服务访问日志、数据接入运行日志、通知页加载新构建资源 `index-o0A6PWvX.js`，分页可见，时间戳之后新增 warn/error 为 `[]`。
