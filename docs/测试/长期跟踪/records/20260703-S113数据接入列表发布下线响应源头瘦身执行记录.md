## 修复摘要

- 保留原 `publish(id)`、`offline(id)` 完整详情接口，继续服务编辑页发布/下线后的详情刷新。
- 新增列表专用接口：`POST /data-ingestion-services/{id}/publish-summary`、`POST /data-ingestion-services/{id}/offline-summary`，返回 `DataIngestionServiceListView`。
- `DataIngestionServicesView.vue` 列表页发布/下线改用 summary 接口，动作后仍执行 `loadServices()` 重拉当前页，保持分页、排序、状态补位正确。
- 后端列表查询抽出 `selectTableListColumns()`，summary 返回只按列表展示字段查询，不读取 `fieldMappingsJson`、`sourceBindingsJson`、`writerOptionsJson`、`webserviceConfigJson`。
- 发布/下线写状态改为 `LambdaUpdateWrapper` 显式 `set(status, updatedAt, serviceKey, endpointPath)`，避免空实体默认空集合/空 Map 覆盖 JSON 字段。

## 注意事项

- 本轮曾在早期实现中发现一个真实风险：使用新实体做更新时，实体字段默认空集合/空 Map 会把接入服务 JSON 配置覆盖为空。
- 已将更新逻辑修正为 `LambdaUpdateWrapper` 显式 set 字段，并通过 API、UI、详情复核确认 S12 长期服务配置已恢复：字段映射 10 条、source binding 1 条、来源 `BODY`。
- 本轮没有把列表当前页重新拉取判为问题。按用户补充要求，分页该拉取仍拉取，刷新状态也可保留；后续重点继续排查隐藏详情读取、大 JSON 源头读取和跨上下文刷新。
