- 数据策略：本轮未清理长期项目和长期测试库数据，未新增一次性数据。

## 发现的问题

涉及页面：
- `/statistics`

涉及接口：
- `POST /api/v1/models/statistics`
- `POST /api/v1/statistics/charts/query`

代码复核确认：
1. 前端 `ModelStatisticsView.vue` 的执行分析会先调用 `studioApi.models.statistics(buildRawStatisticsRequest())`，随后对趋势、柱图、饼图、TopN 分别调用 4 次 `studioApi.statistics.queryChart(...)`。
2. 修复前 `DataModelStatisticsService.resolveStatisticsData()` 会通过 `DataModelAttrIndexMapper.selectList(...)` 读取匹配模型的目标字段索引明细行。
3. `DataModelStatisticsWorkspaceService` 的图表查询复用上述解析链路，导致一次页面分析最多重复 5 次读取同一批目标字段索引明细。
4. 趋势图还额外读取 `DataModelEntity` 明细后在 Java 内存按创建时间聚合。
5. 统计分析页只需要命中模型数、命中条目数、去重值、数值聚合、值分桶和趋势桶，不应随目标字段索引明细行增长而重复把明细拉到应用层。

## 本轮整改

1. 新增统计聚合 SQL provider
   - `DataModelStatisticsSqlProvider#selectStatisticsSummary`
   - `DataModelStatisticsSqlProvider#selectStatisticsValueBuckets`
   - `DataModelStatisticsSqlProvider#selectStatisticsNumericBucketCounts`
   - `DataModelStatisticsSqlProvider#selectStatisticsTrendBuckets`

2. 新增聚合结果模型
   - `DataModelStatisticsSummaryAggregate`
   - `DataModelStatisticsBucketAggregate`
   - `DataModelStatisticsBucketRange`
   - `DataModelStatisticsTrendAggregate`

3. 改造统计服务
   - `DataModelStatisticsService.statistics()` 改为直接使用源端聚合结果。
   - `resolveStatisticsData()` 只保留目标 schema、字段、scope、统计类型、匹配模型 ID 和可选条目 unit，不再装载目标字段索引明细。
   - 概览、字符串分桶、数值分桶、趋势桶均由 mapper 聚合查询提供。
   - 保留旧的行级构建方法，供已有单测和兼容入口继续使用。
   - SQL `avg` 结果统一 `setScale(10, HALF_UP)`，保持旧 Java 聚合返回契约。

4. 改造工作台图表服务
   - `DataModelStatisticsWorkspaceService` 的柱图、饼图、TopN 改为调用聚合方法。
   - 趋势图改为调用 `selectStatisticsTrendBuckets`，不再读取 `DataModelEntity` 明细后内存聚合。

5. 增加回归测试
   - `DataModelStatisticsSourceSlimmingRegressionTest#statisticsShouldAggregateBucketsAtSourceWithoutLoadingTargetRows`
   - 断言统计分析调用 summary/value bucket 聚合 mapper。
   - 断言不再调用 `DataModelAttrIndexMapper.selectList(any(Wrapper.class))` 拉取目标字段索引明细。
