## 发现并修复的问题

### BUG-S13-001 开放调用完整日志敏感字段名变体脱敏不完整

- 严重级别：高。
- 复现批次：`LT-S13-SENSITIVE-20260622-0001`，最终回归批次 `20260622002222`。
- 复现步骤：
  1. 调用 `长期回归-S12客户边界大结果集查询服务`。
  2. 在 Header/Body 中传入 `secretToken`、`clientSecret`、`api_key`、`access-key`、`credentialValue` 等字段。
  3. 下载该次开放调用完整日志。
- 修复前实际：
  - `password`、`token`、部分 header 已遮蔽。
  - `secretToken`、`clientSecret`、`api_key` 等字段名变体的值以原文出现在完整日志中。
- 影响范围：
  - 数据服务、数据接入和协议转换共用的开放调用完整日志清洗逻辑。
  - 日志查看、下载、并发下载均可能暴露未覆盖的敏感字段名变体。
- 根因：
  - `OpenServiceInvocationLogSupport.sanitizeSensitiveLog` 只匹配固定敏感字段名，例如 `accessKey`、`secretKey`、`apiKey`。
  - 未覆盖前后缀组合、下划线、连字符、大小写混合及 `credential` 类字段。
- 修复：
  - 新增统一的 `SENSITIVE_NAME_PATTERN`。
  - 扩展 JSON 字段和 assignment 风格字段的脱敏正则，覆盖 `password`、`access[_-]?key`、`secret`、`token`、`private[_-]?key`、`api[_-]?key`、`authorization`、`cookie`、`credential`，并允许字段名前后缀、点、下划线和连字符。
- 修复文件：
  - `backend/studio-infra/src/main/java/com/jdragon/studio/infra/service/OpenServiceInvocationLogSupport.java`
  - `backend/studio-test/src/test/java/com/jdragon/studio/infra/service/DataIngestionInvocationLogSupportTest.java`
- 回归测试：
  - 新增 `shouldMaskSensitiveInvocationLogFieldNameVariants`，覆盖 `secretToken`、`clientSecret`、`api_key`、`access-key`、`credentialValue` 以及 assignment 风格字段。
