## 发现的问题

工作流编辑页“选择采集任务”弹窗只用于绑定已上线采集任务。弹窗展示和绑定需要：

- `id`
- `projectId`
- `updatedAt`
- `name`
- `taskType`
- `sourceCount`

旧实现调用 `GET /api/v1/collection-tasks/online`，该接口返回采集任务表格摘要字段，并且是全量列表。接口适合保留为已有在线任务摘要兼容接口，但弹窗不是主表格场景，实际额外返回和源头读取：

- `tenantId`
- `deleted`
- `createdAt`
- `status`
- `targetDatasourceName`
- `targetDatasourceTypeCode`
- `targetModelName`
- `targetModelPhysicalLocator`
- `schedule`

这违反“表格类接口只服务表格视图；绑定/下钻场景应新增源头轻量视图接口”的约定。

## 本轮整改

1. 保留旧接口
   - `/collection-tasks/online` 保持兼容，不直接收窄字段。

2. 新增工作流绑定候选接口
   - 新增 `CollectionTaskWorkflowOptionView`。
   - 新增 `GET /api/v1/collection-tasks/workflow-options`。
   - `CollectionTaskService.listWorkflowOptions(...)` 按当前租户、当前项目、`ONLINE` 状态分页查询。
   - 源头 select 仅包含 `id/projectId/updatedAt/name/taskType/sourceCount`，不读取 schedule，也不读取采集任务详情 JSON。

3. 前端替换调用点
   - `WorkflowEditorView` 的采集任务弹窗改用 `collectionTasks.workflowOptions(...)`。
   - 搜索、刷新、分页改为服务端分页。
   - 选中节点保留已绑定任务名称、类型和源数量的本地兜底显示。
