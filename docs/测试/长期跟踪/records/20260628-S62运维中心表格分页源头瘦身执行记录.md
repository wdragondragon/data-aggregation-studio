## 发现的问题

`/ops-center` 的多个表格区块固定使用小页展示，前端默认 `PAGE_SIZE=8`，但旧后端实现先按时间窗口全量查询，再在 Java 中过滤、排序、分页：

- `queryQueue()`
- `queryRuns()`
- `queryServiceEvents()`
- `queryIngestionEvents()`
- `queryLogEvents()`

这些接口用于运维中心表格视图，不承担详情下钻的完整数据获取。旧实现会随着运行记录、服务访问日志、接入访问日志增长而放大首屏查询成本，违反“表格类接口只返回表格视图所需范围，并且从源头轻量分页”的约定。

## 本轮整改

1. 源头分页
   - 运维中心队列、运行事件、服务异常、接入异常、日志异常 5 个表格查询改为 MyBatis-Plus `selectPage`。
   - 保留原接口路径和 `PageView` 返回契约，不影响前端调用。

2. SQL 条件下推
   - 队列、运行、服务访问、接入访问、日志异常筛选条件下推到 `LambdaQueryWrapper`。
   - 服务/接入异常不再全量取日志后 Java 判断异常或慢调用。
   - 日志异常不再全量取运行记录后 Java 判断日志状态。

3. 保留必要例外
   - `queryWorkers()` 仍保留内存分页，因为 Worker 分组视图由项目绑定和在线租约聚合得到，数据规模小，且不是单表直接分页场景。
