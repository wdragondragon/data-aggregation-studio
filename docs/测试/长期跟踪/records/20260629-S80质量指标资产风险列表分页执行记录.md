## 发现的问题

涉及页面：
- `/quality-metrics`

涉及接口：
- 旧接口：`POST /api/v1/quality-metrics/assets/query`
- 新接口：`POST /api/v1/quality-metrics/assets/page`

代码复核确认：
1. 资产洞察 Tab 的“资产风险列表”只是表格视图，页面首屏只需要当前页资产名称、数据源、健康分、风险指数、问题数、覆盖维度和最近执行。
2. 修复前前端调用 `studioApi.qualityMetrics.queryAssets(...)` 获取完整数组，然后用 `useClientPagination` 在浏览器端分页。
3. 旧接口 `/quality-metrics/assets/query` 适合保留给兼容和非分页场景，不应直接改返回结构。
4. 因表格分页语义明确，应新增分页接口，并让前端资产风险列表只取当前页。

## 本轮整改

1. 保留旧全量查询接口
   - `POST /quality-metrics/assets/query` 保持返回 `List<QualityAssetRiskView>`。

2. 新增分页查询接口
   - `QualityAssetQueryRequest` 增加 `pageNo`、`pageSize`。
   - `QualityMetricsController#queryAssetsPage(...)` 暴露 `POST /quality-metrics/assets/page`。
   - `QualityMetricsService#queryAssetsPage(...)` 返回 `PageView<QualityAssetRiskView>`。
   - 分页参数默认 `pageNo=1`、`pageSize=10`，最大 `pageSize=200`。

3. 前端资产洞察 Tab 改为服务端分页
   - `QualityMetricsView.vue` 不再对资产列表使用 `useClientPagination`。
   - `loadAssets()` 调用 `queryAssetsPage(...)`，只保存当前页 `items` 和 `total`。
   - 页码、页大小、资产过滤条件变化时只刷新资产风险列表，不扩大刷新到整个质量指标页。
   - `QualityMetricsAssetsTab.vue` 增加分页事件上抛。

4. SDK 补充分页方法
   - `frontend/packages/api-sdk/src/client.ts` 增加 `queryAssetsPage(...)`。
   - `frontend/packages/api-sdk/src/types.ts` 同步请求类型字段。

5. 增加回归测试
   - `MetricsSourceSlimmingRegressionTest#qualityAssetsPageShouldReturnRequestedPageAndReuseSummarySources`
   - 校验 `pageNo=2,pageSize=1` 只返回 1 条。
   - 校验质量指标仍复用轻量数据源摘要和模型摘要页，不回退到完整 `list()`。
   - 校验运行记录查询不读取 `payload_json`、`log_file_path`。
