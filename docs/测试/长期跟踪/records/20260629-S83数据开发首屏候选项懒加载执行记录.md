# S83 数据开发首屏候选项懒加载执行记录

## 背景

- 日期：2026-06-29
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：继续深挖 `/data-development` 是否存在首屏页面未展示编辑器候选控件，却预取下钻式编辑数据或刷新范围过大的问题。
- 数据策略：本轮未新增、未清理长期测试数据。

## 发现的问题

涉及页面：
- `/data-development`

涉及前端调用：
- `GET /api/v1/data-development/tree`
- `GET /api/v1/data-development/directories`
- `GET /api/v1/data-development/sql-datasources/options`
- `GET /api/v1/script-environments/options?enabledOnly=true`

代码和页面复核确认：
1. `/data-development` 首屏在未选择脚本时只展示脚本树和“请选择脚本/新建脚本”的空态。
2. SQL 数据源下拉只在新建/打开 SQL 脚本编辑器时可见。
3. Java 运行环境下拉只在新建/打开 Java 脚本编辑器时可见。
4. 修复前 `refreshAll()` 首屏和顶部刷新固定并发加载脚本树、目录、SQL 数据源候选、Java 运行环境候选。
5. 这属于刷新范围过大：当前视图未展示候选项，却预取编辑器下钻数据；在数据源或运行环境数量增长后，会拖慢脚本树首屏。

## 本轮整改

1. 拆分数据开发刷新范围
   - `refreshAll()` 只加载首屏可见的脚本树和目录。
   - 编辑器未打开时，不再请求 SQL 数据源候选和 Java 运行环境候选。

2. 候选项按需加载
   - 新增 `loadSqlDatasourceOptions()`。
   - 新增 `loadScriptEnvironmentOptions()`。
   - 新增 `ensureEditorReferenceData()`，根据当前脚本类型按需加载候选项。
   - 新建 SQL 脚本时加载 SQL 数据源候选。
   - 打开 SQL 脚本详情时加载 SQL 数据源候选，并保持 SQL 提示加载链路。
   - 打开或切换到 Java 脚本时加载运行环境候选，并保持默认运行环境选择逻辑。

3. 保持既有行为
   - 脚本树和脚本列表后端轻量查询不变。
   - 点击脚本详情仍按 `GET /data-development/scripts/{id}` 获取完整 `content`。
   - 如果编辑器已经打开，顶部刷新会刷新当前编辑器所需候选项。
   - 不改变保存、移动、删除的既有局部更新逻辑。
