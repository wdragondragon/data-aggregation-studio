## 本轮发现

1. `GET /quality-rules` 为表格列表接口，但仍返回 `logicSql/inputParams/outputParams` 等规则详情字段。
2. `GET /quality-tasks` 与 `GET /quality-tasks/online` 为任务列表/选择接口，但仍返回 `resolvedSqlPreview/parameterBindings/outputParams/alertConfigs/ruleSnapshot/whereClause` 等详情字段。
3. `GET /runs?includeRunRecords=true` 为运行历史列表接口，但仍返回 `payloadJson/resultJson`，长期项目 255 条运行记录时响应约 760KB。
4. 质量规则启停、质量任务发布后会整页刷新列表，更新范围超过单行状态变化所需范围。

## 代码判断

1. 质量规则列表页仅使用规则名称、编码、维度、粒度、作用域、启用状态、创建人、时间和可编辑/可删除标记；编辑页通过 `/quality-rules/{id}` 获取完整 SQL 与参数。
2. 质量任务列表和工作流质量任务选择弹窗仅使用任务、规则、数据源、模型、字段、状态等摘要字段；编辑页通过 `/quality-tasks/{id}` 获取完整 SQL 预览、参数绑定和告警配置。
3. 采集/质量运行列表只需要运行摘要、指标、消息、时间、worker 与日志记录 id；日志抽屉已通过 `/runs/{id}` 和 `/runs/{id}/log` 下钻获取完整详情。

## 修复内容

1. 新增后端轻量 DTO：
   - `QualityRuleListView`
   - `QualityTaskListView`
   - `QueuedTaskListView`
   - `RunRecordListView`
2. `GET /quality-rules` 改为 `PageView<QualityRuleListView>`；详情和 options 接口保留完整 `QualityRuleView`。
3. `GET /quality-tasks` 与 `/quality-tasks/online` 改为质量任务摘要；详情接口保留完整 `QualityTaskDefinitionView`。
4. `GET /runs` 改为运行摘要列表，不再返回 `payloadJson/resultJson`；`/runs/{id}` 保留完整运行详情。
5. `RunRecordListView` 增加 `durationMs`，后端从 `resultJson.durationMs`、`payloadJson.durationMs` 或开始/结束时间推导，前端列表不再依赖大 JSON 字段。
6. 质量规则启停、质量任务发布改为 patch 当前行，不再整页刷新列表。
