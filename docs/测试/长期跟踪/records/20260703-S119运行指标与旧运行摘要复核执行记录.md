## 发现问题

| 编号 | 模块 | 问题 | 是否真实存在 | 是否修复 |
|---|---|---|---|---|
| FIX-S119-001 | 运行记录 / 指标摘要 | `/runs` 列表源头已不读取 `result_json/payload_json`，但旧格式运行记录缺少指标列时，`RunMetricSummaryMapper.fromEntity()` 会把缺失的 `successRecords/transformerTotalRecords` 推导成 `0`，形成“未取到指标但展示为 0”的误导；原 API 回归测试也仍要求列表从旧 `result_json` 恢复指标，与当前源头瘦身契约冲突 | 是 | 是 |

## 修复范围

| 文件 | 说明 |
|---|---|
| `backend/studio-infra/src/main/java/com/jdragon/studio/infra/service/RunMetricSummaryMapper.java` | `fromEntity()` 在实体未选出指标字段时不再凭空推导 `successRecords=0` 或 `transformerTotalRecords=0`；只有存在 `readSucceedRecords` 或 transformer 子指标时才计算派生值。 |
| `backend/studio-test/src/test/java/com/jdragon/studio/test/RunMetricsApiRegressionTest.java` | 测试契约改为：列表轻量返回旧记录指标为空，不读取旧 JSON；详情 `/runs/{id}` 按 id 读取完整记录并恢复旧格式 `totalRecords/errorRecords/transformer*` 指标；同时补齐 `collection_task_metric_binding` 摘要夹具，匹配 S74 后的运行指标筛选项源头。 |
