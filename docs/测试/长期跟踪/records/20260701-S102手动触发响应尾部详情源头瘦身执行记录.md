## 问题确认

| 编号 | 模块 | 现象 | 真实存在 | 是否需要修复 |
|---|---|---|---|---|
| S102-TRIGGER-001 | 工作流/采集/质量手动触发 | 三类手动触发接口执行成功后再次读取完整定义并作为响应返回，但前端完全忽略响应体 | 是 | 是 |

根因：

- `WorkflowController.trigger`、`CollectionTaskController.trigger`、`QualityTaskController.trigger` 在调用调度服务后分别返回完整详情。
- 完整详情包含画布定义、采集配置、质量规则绑定等大结构，和手动触发按钮的实际 UI 反馈无关。
- 前端 `WorkflowsView.vue`、`CollectionTasksView.vue`、`QualityTasksView.vue` 只展示成功提示并刷新当前页，不读取返回对象。

## 观察项

- `GET /actuator/health` 在本轮重启后持续返回 `503 {"status":"DOWN"}`，但登录、列表、三类触发 API 和 build-nginx 页面均可用。日志显示 `StudioSchemaAutoUpgradeRunner` 已进入自动升级流程，业务请求正常响应；该问题未归因到 S102 代码改动，后续可作为运行基线专项排查。
- 手动探测过程中曾有一次命令行 JSON 转义错误导致登录接口返回 500，并写入后端错误日志；该请求体不是前端真实请求，不作为产品缺陷。

## 结论

- 真实问题已修复。
- 三类手动触发接口不再在响应尾部读取完整工作流、采集任务或质量任务详情，前端 SDK 契约同步为 `void`。
- 页面触发后的当前页刷新仍保留，符合“分页该拉取还是拉取刷新状态”的边界。
- 后续涉及 `WorkflowController.trigger`、`CollectionTaskController.trigger`、`QualityTaskController.trigger`、`DispatchService`、手动触发按钮或触发后刷新逻辑时，至少复跑 `ManualTriggerResponseSlimmingRegressionTest`、`npm run build:web`、三类 trigger API 和 build-nginx `/workflows`、`/collection-tasks`、`/quality-tasks`。
