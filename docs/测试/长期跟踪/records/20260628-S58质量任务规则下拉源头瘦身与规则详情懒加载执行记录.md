# S58 质量任务规则下拉源头瘦身与规则详情懒加载执行记录

## 背景

- 日期：2026-06-28

- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：继续结合页面和代码排查前端可达点中过度获取数据的接口，重点复核 `/quality-tasks/new` 中质量规则下拉。

## 发现的问题

质量任务编辑页的规则下拉只用于展示和选择规则，初始下拉需要：

- `id`
- `ruleName`
- `ruleCode`
- `scopeType`
- `ruleDimension`
- `granularity`
- `supportedDatasourceTypes`
- `enabled`

旧实现调用 `GET /api/v1/quality-rules/options`，返回完整 `QualityRuleView`，同时批量读取：

- `logicSql`
- `description`
- `createdBy/createdByName`
- `editable/deletable`
- `inputParams`
- `outputParams`

质量任务页面确实需要 SQL 模板和输入/输出参数，但只在用户选中具体规则后用于参数绑定、告警配置、SQL 预览和保存，不应在规则下拉刷新时批量加载所有规则详情。

## 本轮整改

1. 保留旧完整接口
   - `/quality-rules/options` 继续返回完整规则，避免破坏已有依赖。

2. 新增轻量选项接口
   - 新增 `QualityRuleOptionView`。
   - 新增 `GET /api/v1/quality-rules/option-summaries`。
   - `QualityRuleService.optionSummaries(...)` 源头只 select `id/tenantId/projectId/deleted/ruleName/ruleCode/scopeType/ruleDimension/supportedDatasourceTypesJson/granularity/enabled`。
   - 不读取 `logicSql`、`description`、`createdBy`、时间字段，也不访问输入/输出参数子表。

3. 前端按需详情
   - `QualityTaskEditorView` 的规则下拉改用 `qualityRules.optionSummaries()`。
   - 选中规则、编辑页加载既有任务、预览/校验/保存前，通过 `qualityRules.get(id)` 确保完整规则详情已加载。
   - `QualityRuleSelectionSection` 的下拉项改为 `QualityRuleOptionView`，详情面板仍使用完整 `QualityRuleView`。
