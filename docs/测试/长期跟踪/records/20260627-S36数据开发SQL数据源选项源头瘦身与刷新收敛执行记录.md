## 本轮发现

1. `/data-development` 首屏通过 `/data-development/datasources` 加载 SQL 数据源下拉。该接口返回完整 `DataSourceDefinition`，长期项目 4 条响应约 15.9KB，包含 `technicalMetadata`、`businessMetadata`、`recentConnectionTests`、`connectionFingerprint` 等下拉不需要字段。
2. 代码侧确认数据开发页、数据服务编辑页、质量规则编辑页、质量任务编辑页只使用数据源 `id/name/typeCode/schemaVersionId/enabled/executable` 等摘要字段，不需要连接配置、业务元数据或连接测试历史。
3. 数据开发页目录保存、节点移动、节点删除后调用 `refreshAll()`，会同时重拉树、目录、SQL 数据源、脚本环境；单个结构变更的刷新范围过宽。

## 修复内容

1. 新增 `DataSourceOptionView`，只包含数据源选项需要字段。
2. `DataSourceService.listBasicOptionsByTypes()` 从源头只选择 `id/tenant/project/deleted/createdAt/updatedAt/name/typeCode/schemaVersionId/enabled/executable`，并按 SQL 可执行类型过滤。
3. 新增 `GET /api/v1/data-development/datasource-options`，保留旧 `/data-development/datasources` 作为完整定义兼容接口。
4. 数据开发页、数据服务编辑页、质量规则编辑页、质量任务编辑页改用 `listSqlDatasourceOptions()`。
5. 数据开发页写后刷新拆分：
   - 首屏/项目切换仍执行 `refreshAll()` 初始化。
   - 目录保存、目录移动、目录删除只刷新树和目录。
   - 脚本移动、脚本删除只刷新树。

## 是否需要修复

需要，已修复。原因是 SQL 数据源下拉存在完整数据源定义过取，且目录/脚本结构单点变更后重拉整页初始化数据，不符合当前 Studio 的轻量视图和窄刷新约定。
