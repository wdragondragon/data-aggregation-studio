- 测试账号：`admin/admin123`
- 数据策略：长期测试数据不清理；本轮未保存任何业务对象，复用长期 MySQL8 数据源和模型。

## 本轮发现

1. `/collection-tasks/new` 的源模型和目标模型下拉原先调用 `studioApi.models.listByDatasource(...)`，即 `GET /models/datasource/{datasourceId}`。
2. 该完整模型接口会批量返回每个模型的 `technicalMetadata/businessMetadata`。长期项目主 MySQL8 数据源当前 31 个模型，完整列表约 46.2KB，并包含技术/业务元数据。
3. 采集任务绑定区的源/目标模型下拉只展示模型名称并提交 `modelId`；字段映射、主键候选、HTTP/SOAP 协议模式和增量字段只依赖已选模型详情。
4. 因此页面不需要在选择数据源时批量读取所有模型完整定义，应改为摘要列表加已选模型详情按需加载。

## 修复内容

1. `CollectionTaskBindingSection.vue` 的模型选项类型由 `DataModelDefinition[]` 改为 `DataModelListView[]`，下拉继续只展示模型名称。
2. `CollectionTaskEditorView.vue` 的数据源模型缓存改为保存 `DataModelListView[]`，`ensureModels(...)` 改为调用 `studioApi.models.listSummariesByDatasource(..., { pageNo: 1, pageSize: 5000 })`。
3. 新增 `modelDetailCache`，编辑已有采集任务、切换源模型、切换目标模型时通过 `studioApi.models.get(modelId)` 按需读取完整模型详情。
4. 所有字段映射、主键、HTTP/SOAP 协议元数据和动态运行参数仍从选中模型详情读取，不改变采集任务保存和预览契约。
5. 补充采集任务模型详情不可用的中英文提示，避免详情加载失败时显示 i18n key。

## 是否需要修复

需要，已修复。原因是采集任务编辑页模型下拉属于选项列表，只有已选模型才需要字段和协议元数据；原实现选择数据源即批量加载完整模型定义，属于真实过取。

## 剩余风险

1. 数据开发 SQL 提示仍通过完整模型列表获取所有表和列，本轮未改。该场景确实需要列提示，但后续更适合新增“SQL 提示源”轻接口，从源头只返回表名、模型名和列名。
2. 本轮不改变后端完整模型接口契约，也不改变采集任务保存、预览和运行配置结构。
