## 本轮发现

`/dashboard` 首屏为了展示计数、最近工作流、最近运行、脚本构成和可执行数据源类型，并发调用 7 个通用接口：

- `GET /datasources`
- `GET /workflows`
- `GET /catalog/capabilities`
- `GET /runs?includeRunRecords=false`
- `GET /collection-tasks`
- `GET /data-development/scripts`
- `GET /workflow-runs?pageNo=1&pageSize=6`

这些接口各自适合保留给原页面使用，但 dashboard 只需要聚合计数和少量最近项。实测长期项目旧 fan-out 总响应约 35,120 bytes；其中运行队列还会为名称解析读取完整采集任务视图，不符合“概览/表格轻量源头取数”的约定。

## 修复内容

1. 新增 `StudioDashboardView`，只返回 dashboard 需要的计数、最近项和可执行数据源类型。
2. 新增 `StudioDashboardService.overview()` 和 `DashboardController GET /api/v1/dashboard/overview`。
3. 数据源、工作流、采集任务、脚本、运行服务新增轻量统计/最近项方法：
   - 数据源：直接 `count`
   - 工作流：发布数 `count`、最近 5 条限定字段、日程按 id 批量补齐
   - 采集任务：上线数直接 `count`
   - 脚本：按类型 `count`，最近 4 条限定字段且不读取 `content`
   - 队列：直接统计 `QUEUED/RUNNING`
4. `DashboardView.vue` 首屏改为只调用 `studioApi.dashboard.overview()`，删除 7 个旧列表/能力矩阵请求。

## 是否需要修复

需要，已修复。原因是 dashboard 首屏属于概览聚合页面，不应通过多个通用列表接口读取远超展示范围的数据。
