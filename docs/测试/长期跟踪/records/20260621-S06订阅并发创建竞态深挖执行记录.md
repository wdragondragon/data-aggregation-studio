## 修复摘要

- 三张订阅表新增“启用状态下同一服务、同一订阅名唯一”的持久层约束：
  - MySQL：新增生成列 `active_subscription_name`，值为 `enabled=1` 时的 `subscription_name`，并建立唯一索引 `(service_id, active_subscription_name)`。
  - SQLite：新增部分唯一索引 `(service_id, subscription_name) where enabled = 1`。
- `StudioSchemaUpgradeService` 在建唯一约束前先规整历史重复启用数据：每组保留最大 `id` 为启用，其余置为停用；不删除历史记录。
- 数据接入和协议转换在插入/启用遇到唯一键冲突时返回 `BAD_REQUEST`，避免暴露 500。
- 数据服务保留“同名创建可轮换已有订阅”的兼容语义；并发下允许部分请求返回 `BAD_REQUEST`，但最终只能保留一条同名启用订阅。
- 初始化 SQL 同步补齐 MySQL/SQLite 约束，避免新环境缺失。
