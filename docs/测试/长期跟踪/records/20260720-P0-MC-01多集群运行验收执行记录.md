### 真实三集群定向与远端 HTTP 闭环

验收期间曾在同一真实 MySQL 下同时运行默认本地执行集群、`C46` 和 `C50` 三个不同集群身份。以下记录只保留集群别名和业务结论，临时资源 ID、内部认证值、登录信息及完整受管端点均不写入本文：

- 三个集群的 Worker lease 和实例心跳在验收期间可同时存在。`C46`、`C50` Worker 当时以显式集群身份在 `LEGACY` 模式运行，并且只领取 `targetClusterId` 指向自身集群的任务；该结果不能替代正式 `ENFORCED` 切换演练。
- 分别创建并执行一个简单 Python 脚本到 `C46`、`C50`。两次运行均成功，运行记录的请求集群与实际集群一致，实际集群编码和 Worker 实例也分别归属目标集群；未观察到跨集群误领。
- 为 `C46`、`C50` 配置受管 HTTP 端点后，两个端点的内部健康测试均成功。测试响应只记录状态和脱敏摘要，没有回显内部 Token、Header 值或完整地址。
- 对同一临时 HTTP 数据源分别在 `C46`、`C50` 执行连接测试和探测，`C46` 形成 `AVAILABLE / HTTP 200`，`C50` 形成 `UNAVAILABLE / ConnectException`；两条健康结果按运行集群隔离，且不会自动修改数据源适用集群绑定。
- 将临时 JSON `BODY_BRIDGE` 和 XML 协议转换分别定向到 `C46`，从 OMS 对外入口调用后均由 `C46` Worker 请求本地 HTTP mock，成功状态和响应体经 OMS 返回。
- 对应协议转换调用均只写入一条访问日志，请求集群和实际集群均为 `C46`；OMS 控制面没有重复写入第二条访问日志。
- 停止 `C46` Worker 后再次从 OMS 调用目标服务，接口返回 `503`，HTTP mock 请求数没有增加；该结果证明目标集群不可达时不会误走本地执行、重定向到其它集群或自动重试。验证后曾重新启动 `C46` 继续后续验收，最终已按收尾清理步骤停止。

该闭环证明了“共享数据库定向 Claim + 受管 HTTP 端点 + 数据源 A/B 健康隔离 + JSON/XML 协议转换远端执行 + 不可达 `503` + 日志单写”的最小生产形态。它尚不替代正式 `LEGACY -> ENFORCED` 切换演练、SOAP、共享对象存储、其它大型编辑器和 Desktop 实机验收。

### 生产索引残余风险

- 七类资源表在运行配置重新校验时会按 `tenant_id + runtime_cluster_id` 查询，当前未为这些查询额外增加组合索引。
- 数据服务、数据接入和协议转换访问日志按实际集群筛选时，主要复用现有项目与时间索引；大数据量下的过滤成本仍需结合生产分布确认。
- 上线前应基于生产数据基数执行 `EXPLAIN`，确认慢查询后再按实际选择性补充索引，避免在缺少生产证据时提前增加写入和存储成本。
