## 问题确认

| 编号 | 模块 | 现象 | 真实存在 | 是否需要修复 |
|---|---|---|---|---|
| S86-RUN-001 | 运行日志抽屉 | 抽屉概要只需要列表级字段和指标摘要，却调用全量 `/runs/{id}`，读取 payload/result 和日志存储字段 | 是 | 是 |
| S86-RUN-002 | 运行日志分页/下载 | 对象存储日志或 worker 文件日志已可按指针读取，但接口仍先读取全量运行记录；只有历史 fallback 才需要 payload/result | 是 | 是 |

根因：

- `RunLogDrawer.load()` 直接调用 `studioApi.runs.get(id)`。
- `RunService.get(id)` 通过 `runRecordMapper.selectById(id)` 读取整实体，用于保留历史详情诊断能力，但不适合作为抽屉概要接口。
- `RunLogProxyService.viewLog/downloadLog()` 复用 `RunService.getEntity(id)`，导致常规日志路径也读取 `payload_json/result_json`。
- 单条抽屉概要如果复用 `collectionTaskNames()/qualityTaskNames()/workflowNames()`，会为一条运行记录加载当前项目全量名称映射。
