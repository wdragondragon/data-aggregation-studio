# S73 模型列表写后预览过取与刷新收敛执行记录

## 背景

- 日期：2026-06-29
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio/models`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：继续深挖模型中心是否存在“列表页写后下钻数据过取”和“刷新范围过大”的问题。

## 发现的问题

`ModelsView.vue` 在模型列表页保存模型后执行：

```ts
modelPagination.page = 1;
await handleDatasourceChange();
await selectModel(saved);
```

其中 `handleDatasourceChange()` 已经刷新当前模型表格，而 `selectModel(saved)` 会触发 `loadModelPreviewRows(saved.id)`，进一步请求：

```http
GET /api/v1/models/{modelId}/preview
```

该接口最终会走 `DataModelService.preview()` 和数据源能力提供器读取样例数据。样例预览只在模型详情页 `ModelDetailShell` / `ModelDetailOverview` 中展示，模型列表页没有预览区域，因此列表页保存后读取样例数据属于写后下钻数据过取。

同一页面还有两个刷新范围偏大的路径：

- 模型列表工具栏 `刷新` 调用 `refreshModels()`，会重拉数据源选项、元模型摘要、索引队列和模型列表；但用户当前只刷新模型列表和队列状态，不需要重跑整页初始化数据。
- 模型详情页 `refreshDetail()` 会重拉数据源选项和元模型摘要后再加载当前模型详情；详情刷新只需要刷新当前模型详情，模型详情加载过程中会按需补充所需 schema 详情。

此外，直达 `/models?tab=sync-tasks` 时，`activeListTab` watcher 和路由上下文 watcher 都可能触发同步任务列表加载，形成初始化重复请求。

## 本轮整改

1. 列表保存后不再预览
   - 保存模型后只刷新当前模型表格。
   - 不再调用 `selectModel(saved)`，避免列表页请求 `/models/{id}/preview`。

2. 刷新范围收敛
   - `refreshModels()` 只刷新索引队列状态和当前模型表格。
   - `refreshDetail()` 只刷新当前模型详情。
   - 路由或项目上下文变化仍保留 `loadPage()` 初始化路径，用于加载数据源选项和元模型摘要。

3. 直达同步任务 Tab 去重
   - `activeListTab` watcher 取消 `immediate`。
   - 初始化加载由路由上下文 watcher 统一处理，避免直达 `sync-tasks` 时重复请求同步任务列表。
