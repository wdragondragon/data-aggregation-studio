## 背景

- 日期：2026-06-29
- 入口：`http://127.0.0.1:8000/dfs/data-aggregation-studio`
- 账号：`admin / admin123`
- 长期项目：`长期回归测试项目`，项目 ID `2068077680446365698`
- 目标：继续深挖模型中心和数据源页面是否存在“表格只展示少量字段，但接口返回下钻/详情元数据”的过度取数问题。

## 发现的问题

涉及页面：
- `/models`
- `/datasources`

涉及前端入口：
- `ModelSyncTableSelector.vue`
- `DatasourcesView.vue` 的“发现表/已发现模型”弹窗

涉及接口：
- 旧接口：`POST /api/v1/datasources/{id}/discover`
- 新接口：`POST /api/v1/datasources/{id}/discover-options`

代码复核确认：
1. 模型同步弹窗的表格只展示：
   - `name`
   - `physicalLocator`
2. 数据源页面“发现模型”弹窗只展示：
   - `name`
   - `modelKind`
   - `physicalLocator`
3. 修复前两个前端入口都调用旧 `discover`，返回 `ModelDiscoveryResult.models: DataModelDefinition[]`。
4. `DataModelDefinition` 包含 `technicalMetadata` 和 `businessMetadata`。
5. 后端 `AggregationSourceCapabilityProvider#discoverModels(...)` 在发现 RDBMS、文件、队列模型时会为每行构造技术/业务元数据；文件/队列场景还会从数据源元数据派生模型元数据。
6. 当前表格没有编辑、预览、同步详情下钻依赖这些元数据，属于表格视图过度返回详情字段。

## 本轮整改

1. 保留旧 `discover`
   - 旧接口继续用于兼容和可能存在的完整模型发现调用。
   - 不直接削减旧接口字段，避免破坏既有契约。

2. 新增轻量发现结果
   - `ModelDiscoveryOptionResult`
   - `models` 使用 `DataModelDatasourceOptionView`
   - 只返回：
     - `datasourceId`
     - `name`
     - `modelKind`
     - `physicalLocator`
   - 不返回 `technicalMetadata`、`businessMetadata`。

3. 从源头轻量生成
   - 新增 `AggregationSourceCapabilityProvider#discoverModelOptions(...)`
   - RDBMS：只基于 `getTableNames(...)` 的表名生成选项，不构造模型元数据。
   - 文件：只基于文件名生成选项，不构造文件模型元数据。
   - 队列：只基于队列/Topic 名称生成选项，不返回 brokers、consumerGroup 等元数据。

4. 前端改走轻量接口
   - `ModelSyncTableSelector.vue` 调用 `studioApi.datasources.discoverOptions(...)`
   - `DatasourcesView.vue` 的发现弹窗调用 `discoverOptions(...)`
   - SDK 新增 `ModelDiscoveryOptionResult` 和 `discoverOptions(...)`

5. 增加回归测试
   - `DataSourceDiscoveryOptionsSourceSlimmingRegressionTest`
   - 验证轻量发现路径调用 `discoverModelOptions(...)`，不误走旧 `discoverModels(...)`
   - 验证序列化响应不包含 `technicalMetadata`、`businessMetadata`、`password`、`columns`
