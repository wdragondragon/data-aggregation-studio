- 目标：继续深挖表格分页后仍存在的“表面分页、内里全量水合”问题。

## 发现的问题

系统管理资源共享 tab 的表格本身已经走：

- `GET /api/v1/system/resource-shares/page`

但进入 tab 或刷新表格时，前端仍并行调用：

- `GET /api/v1/system/projects`
- `GET /api/v1/system/resource-share-options?resourceType=...`

原因是表格行只有 `sourceProjectId / targetProjectId / resourceType / resourceId`，前端为了显示来源项目、目标项目和资源名称，会预加载当前资源类型下的全部可共享资源选项，以及项目全量列表。

这违反本轮数据获取约定：表格视图应由表格分页接口直接返回当前页展示需要的字段，不能先分页共享记录，再为当前页标签拉取全量候选资源。

## 本轮整改

1. 新增资源共享表格视图
   - 新增 `ResourceShareView`，包含当前页展示需要的：
     - `resourceLabel`
     - `resourceName`
     - `resourceCode`
     - `resourceStatus`
     - `sourceProjectName`
     - `targetProjectName`

2. 后端分页接口源头水合当前页
   - `SystemManagementService.listResourceSharesPage(...)` 改为返回 `PageView<ResourceShareView>`。
   - 先对 `studio_resource_share` 做数据库分页。
   - 只对当前页中的项目 ID 批量查询项目名。
   - 只对当前页中的 `resourceType/resourceId` 按类型批量查询资源标签。
   - 保留旧 `resource-share-options` 接口，继续作为共享弹窗候选项来源。

3. 前端刷新范围收敛
   - `SystemView.vue` 资源共享 tab 首屏只加载 `resourceSharesData`。
   - 表格刷新只刷新分页表格，不再同时刷新项目列表和资源候选。
   - 表格优先使用分页接口返回的 `resourceLabel/sourceProjectName/targetProjectName`。
   - 打开共享弹窗时才懒加载项目和资源候选。
