# 数据服务

## 模块定位

数据服务是读向开放服务能力，用于把数据库模型或 SQL 查询发布为可调用的 REST/SOAP 接口。它适合对外提供查询、分页查询和标准化数据访问能力。

## 适用角色

- API 服务维护人：创建、发布和维护数据服务。
- 数据开发人员：配置查询字段、参数和 SQL。
- 运维人员：查看访问日志、调用趋势和异常信息。

## 入口路径

| 页面 | 路由 | 用途 |
|---|---|---|
| 数据服务 | `/data-services` | 新建、编辑、发布和调试数据服务 |
| 数据服务监控 | `/data-service-metrics` | 查看调用统计和访问日志 |

## 核心概念

- 服务编码：开放调用路径中的服务标识。
- 请求参数：调用方传入的 Query、Body、Header 或 SOAP 参数。
- 返回参数：服务响应中暴露的字段集合。
- 订阅 Token：调用方鉴权凭证。
- WebService 设置：SOAP 版本、Operation、命名空间、响应根节点和响应数据节点。

## 常用操作流程

1. 新建数据服务，填写基础信息。
2. 选择模型查询或 SQL 查询方式。
3. 解析并配置请求参数、返回参数和筛选条件。
4. 配置 REST 或 WebService 发布参数。
5. 创建订阅方和 Token。
6. 使用调试面板验证请求和响应。
7. 发布服务，并把开放 URL 和 Token 提供给调用方。

## 关键配置说明

- SQL 查询应使用参数绑定，避免把外部输入直接拼接进 SQL。
- 分页服务需要明确页码、页大小和返回数据节点。
- WebService 响应数据节点默认可使用 `table.row`，空结果也应保持稳定结构。
- 调试面板用于验证服务响应，不替代调用方生产联调。

## 验收与排障建议

- 调用返回 401：检查订阅 Token、Header 名称和服务发布状态。
- 返回数据为空：检查请求参数、筛选条件、runBatch 等业务参数。
- SOAP 解析异常：检查 SOAP 版本、Envelope 命名空间和 Operation。
- 响应体过大：确认分页参数和返回字段范围。
