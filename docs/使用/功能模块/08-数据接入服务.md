# 数据接入服务

## 模块定位

数据接入服务是写向开放服务能力，用于接收外部 REST/SOAP 请求，并把数据写入目标模型。它适合承接业务系统推送、接口批量写入和标准化数据入库。

## 适用角色

- 数据接入维护人：配置接入服务、字段映射和写入策略。
- 外部系统联调人员：根据开放接口提交数据。
- 运维人员：查看接入日志、写入失败和数据质量问题。

## 入口路径

| 页面 | 路由 | 用途 |
|---|---|---|
| 数据接入服务 | `/data-ingestion-services` | 新建、编辑、发布和调试接入服务 |
| 接入服务监控 | `/data-ingestion-metrics` | 查看接入调用、写入状态和日志 |

## 核心概念

- 目标模型：接入数据最终写入的模型。
- Payload 形态：单对象或数组。
- 数据节点：数组或复杂结构中代表数据记录的节点路径。
- 字段映射：请求字段到目标字段的写入关系。
- 写入模式：追加、覆盖、更新或 upsert 语义。

## 常用操作流程

1. 准备目标数据源和目标模型。
2. 新建数据接入服务，选择目标模型。
3. 配置请求协议、Payload 形态和数据节点。
4. 配置字段映射、默认值和固定字段。
5. 配置 Token 策略和 WebService 参数。
6. 使用调试面板提交样例数据。
7. 查询目标表或模型预览，确认写入结果。
8. 发布服务并交付开放调用信息。

## 关键配置说明

- 数组模式必须明确数据节点，例如 `records.record`。
- SOAP 接入服务需要确认 SOAP 版本、Operation、命名空间和 Body 结构。
- 目标字段类型要与提交值匹配，日期、数字、JSON 字段应在调试阶段覆盖。
- 重复调用是否幂等取决于目标主键和写入模式。

## 验收与排障建议

- 接口成功但无数据：检查数据节点、字段映射和目标写入模式。
- 单条写入成功、批量失败：检查数组节点和每条记录结构。
- 重复执行产生重复数据：确认主键、唯一键和 upsert 配置。
- 目标字段为空：检查请求字段名、父节点路径和默认值配置。
