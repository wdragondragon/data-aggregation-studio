# 工作流编排

## 模块定位

工作流用于把采集任务、质量任务、数据脚本、HTTP 调用和 Shell 脚本编排成 DAG。它承担跨任务依赖、调度触发、节点运行和运行日志管理。

## 适用角色

- 调度管理员：维护工作流编排、发布和调度。
- 数据集成实施人员：把采集、脚本、质量检查串联成业务链路。
- 运维人员：查看工作流运行实例和节点日志。

## 入口路径

| 页面 | 路由 | 用途 |
|---|---|---|
| 工作流 | `/workflows` | 新建、编辑、发布和触发工作流 |
| 运行实例 | `/runs` | 查看工作流运行记录 |
| 运行详情 | `/runs/:workflowRunId` | 查看节点状态、日志和输入输出 |

## 核心概念

- 工作流：由多个节点和连线组成的 DAG。
- 节点：采集任务、质量任务、数据脚本、HTTP、Shell 等执行单元。
- 连线：节点间的依赖关系。
- 发布版本：用于运行的正式工作流配置。
- 运行实例：一次手动或调度触发生成的执行记录。

## 常用操作流程

1. 新建工作流，填写名称、编码和说明。
2. 在画布添加节点并选择节点类型。
3. 绑定具体资源，例如采集任务、脚本或质量任务。
4. 连接节点，形成执行顺序。
5. 保存草稿并发布。
6. 手动触发或配置调度。
7. 在运行实例中查看节点状态和日志。

## 关键配置说明

- 工作流只能运行发布版本，草稿修改后需要重新发布。
- 节点绑定的资源应先独立验证可运行。
- HTTP 节点适合编排轻量接口调用，不替代协议转换服务。
- 调度配置应结合业务窗口、上游数据到达时间和 Worker 负载。

## 验收与排障建议

- 工作流不触发：确认调度状态、Cron、时区和发布版本。
- 某节点失败：进入运行详情查看节点日志和资源配置。
- 下游未执行：检查上游节点状态和连线关系。
- 运行排队：检查 Worker 在线状态和任务队列。
