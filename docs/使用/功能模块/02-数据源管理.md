# 数据源管理

## 模块定位

数据源管理用于维护外部系统连接信息，是模型同步、数据采集、数据开发、开放服务和质量任务的基础。数据源类型由插件和元模型驱动，页面会根据类型渲染对应连接表单。

## 适用角色

- 数据平台管理员：维护全局或项目内数据源连接。
- 数据集成实施人员：创建采集、服务和脚本所需的数据源。
- 运维人员：排查连接失败、权限不足和网络连通问题。

## 入口路径

| 页面 | 路由 | 用途 |
|---|---|---|
| 数据源中心 | `/datasources` | 查询、新建、编辑、测试数据源 |
| 能力矩阵 | `/catalog` | 查看当前环境支持的数据源插件 |

## 核心概念

- 数据源类型：例如 MySQL、FTP/SFTP、MinIO、Kafka、HTTP 等。
- 技术元数据：主机、端口、库名、账号、路径、认证方式等连接参数。
- 纳入管理：决定该数据源是否进入模型同步、采集任务等业务配置范围。
- 启用状态：决定数据源是否允许被后续配置和运行使用。
- 连接状态：列表展示同一租户内相同物理连接的健康快照，取值为未检测、可用、不可用；禁用或未纳管数据源展示为不可测试。
- 连接指纹：由租户、数据源类型和规范化技术元数据计算，用于识别多项目重复配置的同一物理连接。

## 常用操作流程

1. 进入“数据资产 / 数据源中心”。
2. 点击新建数据源，选择数据源类型。
3. 填写名称、分组和连接参数。
4. 点击连接测试，确认网络、账号和权限可用。
5. 保存后在模型中心同步模型，或在数据开发中执行脚本验证。

## 列表连接状态

- 列表不会对每条数据源实时发起连接测试，避免页面加载被外部数据库、消息队列、文件系统或 HTTP 服务阻塞。
- 在列表中点击测试，会调用 `POST /api/v1/datasources/{id}/test`，手动检测优先返回；如果相同连接指纹正在检测，最多等待短时间，未完成则显示检测中，不重复发起外部连接。
- 在编辑抽屉中点击测试连接，会调用 `POST /api/v1/datasources/test`，只验证当前表单内容，不写回健康快照和历史记录。
- 定时检测在后台尽力刷新健康快照，和手动检测使用隔离执行池；定时检测打满并发时会跳过，不长期排队。
- 列表连接状态列展示最近 10 次真实检测记录的点状趋势，绿色代表可用，红色代表不可用，灰色代表无记录。
- 点击点状趋势会调用 `GET /api/v1/datasources/{id}/connection-history?days=7&limit=1000`，查看最近 7 天的检测时间、触发方式、状态、耗时和失败消息。
- 修改数据源类型或技术元数据后会切换连接指纹并重新使用对应健康快照；只修改名称、业务元数据、启用状态、纳管状态或检测超时时，不改变连接指纹。

## 连接检测超时

- 手动检测和定时检测都支持在数据源高级配置中覆盖超时时间，范围为 1 到 120 秒。
- 未填写时采用“数据源覆盖 > 类型默认 > 全局默认”的优先级，默认手动和定时均为 30 秒。
- 对无法响应中断的底层驱动，超时后页面和健康快照会先返回结果；后台线程可能需要等待驱动自行退出，但执行池和单飞租约会避免继续堆积。

## 关键配置说明

- 敏感字段在页面展示和接口返回中应保持掩码，保存时以表单提交值为准。
- 数据库类数据源需要确认读写权限、默认库和字符集。
- 文件类数据源需要确认路径权限、目录存在性和读写模式。
- HTTP 类数据源建议配置稳定的 Base URL，具体 Endpoint 在模型或任务参数中维护。
- Kafka 数据源只维护 `bootstrap.servers`、认证和安全参数；Topic 不再属于连接必填项。连接测试只验证 Broker，Topic 通过模型中心发现并以模型的 `physicalLocator` 作为采集任务的唯一目标。消费组、offset、批量、重试和自动建 Topic 等属于采集任务的执行参数。

## 验收与排障建议

- 连接测试失败：先确认网络连通、账号密码、端口、防火墙和数据库白名单。
- 后续模型同步失败：确认数据源已启用并纳入管理。
- 任务运行时连接失败：检查 Worker 所在机器是否也能访问该数据源。
