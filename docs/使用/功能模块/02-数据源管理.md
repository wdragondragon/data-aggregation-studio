# 数据源管理

## 模块定位

数据源管理用于维护外部系统连接信息，是模型同步、数据采集、数据开发、开放服务和质量任务的基础。数据源类型由插件和元模型驱动，页面会根据类型渲染对应连接表单。

## 适用角色

- 数据平台管理员：维护全局或项目内数据源连接。
- 数据集成实施人员：创建采集、服务和脚本所需的数据源。
- 运维人员：排查连接失败、权限不足和网络连通问题。

## 入口路径

| 页面 | 路由 | 用途 |
|---|---|---|
| 数据源中心 | `/datasources` | 查询、新建、编辑、测试数据源 |
| 能力矩阵 | `/catalog` | 查看当前环境支持的数据源插件 |

## 核心概念

- 数据源类型：例如 MySQL、FTP/SFTP、MinIO、Kafka、HTTP 等。
- 技术元数据：主机、端口、库名、账号、路径、认证方式等连接参数。
- 纳入管理：决定该数据源是否进入模型同步、采集任务等业务配置范围。
- 启用状态：决定数据源是否允许被后续配置和运行使用。
- 连接状态：列表展示最近一次已保存数据源连接测试快照，取值为未检测、可用、不可用；禁用或未纳管数据源展示为不可测试。

## 常用操作流程

1. 进入“数据资产 / 数据源中心”。
2. 点击新建数据源，选择数据源类型。
3. 填写名称、分组和连接参数。
4. 点击连接测试，确认网络、账号和权限可用。
5. 保存后在模型中心同步模型，或在数据开发中执行脚本验证。

## 列表连接状态

- 列表不会对每条数据源实时发起连接测试，避免页面加载被外部数据库、消息队列、文件系统或 HTTP 服务阻塞。
- 在列表中点击测试，会调用 `POST /api/v1/datasources/{id}/test`，测试完成后写回 `connectionStatus`、`lastConnectionTestAt`、`lastConnectionTestMessage`、`lastConnectionTestDurationMs`。
- 在编辑抽屉中点击测试连接，会调用 `POST /api/v1/datasources/test`，只验证当前表单内容，不写回列表状态。
- 修改数据源类型、schema 绑定或技术元数据后，连接状态会重置为未检测；只修改名称、业务元数据、启用状态或纳管状态时保留最近一次测试快照。

## 关键配置说明

- 敏感字段在页面展示和接口返回中应保持掩码，保存时以表单提交值为准。
- 数据库类数据源需要确认读写权限、默认库和字符集。
- 文件类数据源需要确认路径权限、目录存在性和读写模式。
- HTTP 类数据源建议配置稳定的 Base URL，具体 Endpoint 在模型或任务参数中维护。

## 验收与排障建议

- 连接测试失败：先确认网络连通、账号密码、端口、防火墙和数据库白名单。
- 后续模型同步失败：确认数据源已启用并纳入管理。
- 任务运行时连接失败：检查 Worker 所在机器是否也能访问该数据源。
