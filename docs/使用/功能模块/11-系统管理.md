# 系统管理

## 模块定位

系统管理用于维护租户、项目、用户、成员、角色和权限，是 Studio 多租户、多项目隔离和菜单权限控制的基础。

## 适用角色

- 系统管理员：维护全局配置、租户和系统角色。
- 租户管理员：维护租户下项目和成员。
- 项目管理员：维护项目成员和项目级角色。

## 入口路径

| 页面 | 路由 | 用途 |
|---|---|---|
| 系统管理 | `/system` | 管理租户、项目、成员、角色和权限 |
| 访问申请中心 | `/access-center` | 审批或提交项目访问申请 |

## 核心概念

- 用户：登录 Studio 的账号主体。
- 租户：隔离用户、项目和资产的最高业务单元。
- 项目：承载数据源、模型、任务、服务和日志的工作空间。
- 角色：决定菜单可见性和操作权限。
- 成员关系：用户在租户或项目中的授权关系。

## 常用操作流程

1. 系统管理员创建或维护租户。
2. 租户管理员创建项目并分配项目管理员。
3. 项目管理员添加成员或处理访问申请。
4. 为成员配置合适角色。
5. 成员刷新权限或重新登录后进入项目。

## 关键配置说明

- 管理权限应按最小权限原则授予。
- 项目资产默认按项目隔离，跨项目使用需显式授权或重新配置。
- 菜单可见性与角色和项目上下文有关。
- 删除或停用成员前应确认其名下任务、服务和调度责任。

## 验收与排障建议

- 用户看不到项目：检查成员关系、项目状态和权限刷新。
- 用户看不到菜单：检查角色是否包含对应业务权限。
- 误操作风险高的账号：降低角色权限或迁移到项目级权限。
