# Nacos 多版本连接配置说明

适用仓库：`C:\dev\ideaProject\cloud-parent-springboot3`  
文档日期：`2026-04-25`  
适用代码：当前 `DataAggregation/data-aggregation-studio/backend/studio-nacos-compat-core` 最终实现  
适用消费方：studio backend 直接依赖；cloud-parent 通过 `platform-starter-config` / `platform-starter-discovery` / gateway 侧依赖消费。

本文只说明当前代码实际支持的配置面，不引用旧版 starter 的历史行为。

## 1. 版本结论

当前仓库统一兼容以下 4 个目标版本：

- `1.3.2`
- `2.4.0`
- `2.5.1`
- `3.2.1`

分档结论如下：

| Nacos 版本 | `AUTO` 模式下的默认判代 | 推荐 `platform.nacos.compat.mode` | 实际访问路径 | 认证方式 |
| --- | --- | --- | --- | --- |
| `1.3.2` | `LEGACY` | `LEGACY` 或 `AUTO` | `/nacos/v1/*` HTTP | 用户名密码换取 `accessToken` |
| `2.4.0` | `LEGACY` | `LEGACY` 或 `AUTO` | `/nacos/v1/*` HTTP | 用户名密码换取 `accessToken` |
| `2.5.1` | `MODERN` | `AUTO` 或 `MODERN` | `nacos-client 3.x` | 用户名密码 / `accessKey+secretKey` |
| `3.2.1` | `MODERN` | `AUTO` 或 `MODERN` | `nacos-client 3.x` | 用户名密码 / `accessKey+secretKey` |

补充说明：

1. 当前代码不支持手工直接配置 `accessToken`。
2. `1.x/2.4.x` 的 `accessToken` 登录方式是：配置 `spring.cloud.nacos.username/password`，由兼容层自动请求 `/nacos/v1/auth/login`。
3. `AUTO` 模式会先探测 modern，再回退探测 legacy。
4. `2.5.1+` 即使 `v3 state` 不可达，也可能通过 `v1 state` 的版本号被判成 `MODERN`。

## 2. 先看最小必填项

下面这张表只列“真正决定能不能连上”的最小配置。

| 配置项 | 谁需要填 | 是否必填 | 填写后的效果 | 不填的结果 |
| --- | --- | --- | --- | --- |
| `spring.application.name` | 需要注册服务的应用 | 条件必填 | 作为默认服务名注册到 Nacos；也常用于拼接默认 `dataId` | 若未同时配置 `spring.cloud.nacos.discovery.service`，注册服务名可能为空 |
| `spring.config.import=nacos:...` | 需要配置中心的应用 | 条件必填 | 启动前读取指定 `dataId`，并进入 Boot `Environment` | 不会走配置中心启动加载 |
| `spring.cloud.nacos.config.server-addr` | 需要配置中心的应用 | 条件必填 | 指定配置中心地址 | 启动时直接报错：`spring.cloud.nacos.config.server-addr is blank` |
| `spring.cloud.nacos.discovery.server-addr` | 需要注册/发现的应用 | 条件必填 | 指定注册中心地址 | 注册、发现、心跳、拉服务目录都无法进行 |
| `spring.cloud.nacos.username` | 开启鉴权的 Nacos | 条件必填 | 与 `password` 配合完成认证；legacy 下自动换取 `accessToken` | 服务端若要求认证，会返回 `401/403` 或登录失败 |
| `spring.cloud.nacos.password` | 开启鉴权的 Nacos | 条件必填 | 同上 | 同上 |

## 3.4 兼容层项 `platform.nacos.compat.*`

| 配置项 | 必填/可填 | 推荐值 | 填写后的效果 | 当前代码状态 |
| --- | --- | --- | --- | --- |
| `platform.nacos.compat.mode` | 可填 | 多版本共用时 `AUTO`；固定连 `1.3.2/2.4.0` 时 `LEGACY`；固定连 `2.5.1/3.2.1` 时 `MODERN` | 决定是自动探测，还是直接走 legacy / modern | 已实际消费 |
| `platform.nacos.compat.probe-timeout-ms` | 可填 | 默认即可 | 控制探测连接超时 | 配置属性实际是 `probeTimeout`，支持 Boot 时长格式；代码已实际消费 |
| `platform.nacos.compat.log-probe-detail` | 可填 | 排障时 `true` | 输出 probe 细节和 auto fallback 原因 | 已实际消费，当前默认值是 `true` |
| `platform.nacos.compat.config-read-timeout` | 可填 | 默认即可 | 控制配置读取、注册发现相关 HTTP 超时，也作为 legacy 登录超时 | 已实际消费 |
| `platform.nacos.compat.legacy-long-polling-timeout` | 可填 | legacy 环境默认即可 | 控制 legacy 配置监听长轮询超时 | 已实际消费 |
| `platform.nacos.compat.legacy-beat-interval` | 可填 | legacy 环境默认即可 | 控制 legacy 临时实例心跳周期 | 已实际消费 |

说明：

- 若你写的是 `platform.nacos.compat.probe-timeout-ms=3000` 这种形式，需要确认 Spring Boot 属性绑定是否把它映射到 `Duration`；更稳妥的写法是 `3s`。
- 当前代码默认 `logProbeDetail=true`，不是 `false`。

## 4. 四类版本的推荐写法

## 4.1 连接 `Nacos 1.3.2`

推荐：

- `platform.nacos.compat.mode=LEGACY`
- 配 `username/password`
- `config` 和 `discovery` 的 `server-addr` 都显式写

示例：

```yaml
spring:
  application:
    name: platform-admin-service
  config:
    import:
      - optional:nacos:${spring.application.name}-prod.yaml
  cloud:
    nacos:
      username: nacos
      password: Wjoms_2020
      config:
        server-addr: 192.168.188.129:8848
        namespace: ZCYY
        group: ZCYY_GROUP
        file-extension: yaml
      discovery:
        server-addr: 192.168.188.129:8848
        namespace: ZCYY
        group: ZCYY_GROUP

platform:
  nacos:
    compat:
      mode: LEGACY
```

效果：

- 配置中心走 `/nacos/v1/cs/configs`
- 配置刷新走 `/nacos/v1/cs/configs/listener`
- 注册发现走 `/nacos/v1/ns/*`
- 认证通过 `/nacos/v1/auth/login` 自动换 `accessToken`

## 4.2 连接 `Nacos 2.4.0`

推荐写法与 `1.3.2` 相同。

效果：

- 仍走 `LEGACY` HTTP 兼容层
- 不依赖 modern SDK 路径

## 4.3 连接 `Nacos 2.5.1`

推荐：

- 单包兼容多版本时：`platform.nacos.compat.mode=AUTO`
- 只连 `2.5.1` 时：`platform.nacos.compat.mode=MODERN`

示例：

```yaml
spring:
  application:
    name: gateway-service
  config:
    import:
      - optional:nacos:${spring.application.name}-prod.yaml
  cloud:
    nacos:
      username: nacos
      password: Wjoms_2020
      config:
        server-addr: 192.168.188.129:8848
        namespace: ZCYY
        group: ZCYY_GROUP
        file-extension: yaml
      discovery:
        server-addr: 192.168.188.129:8848
        namespace: ZCYY
        group: ZCYY_GROUP
        cluster-name: DEFAULT

platform:
  nacos:
    compat:
      mode: AUTO
      log-probe-detail: true
```

效果：

- `AUTO` 会先探测 modern
- 配置中心和注册发现优先走 `nacos-client 3.x`
- 若 `v3 state` 不可达，但 `v1 state` 返回版本 `>= 2.5.1`，仍会判为 `MODERN`

## 4.4 连接 `Nacos 3.2.1`

推荐写法与 `2.5.1` 相同。

效果：

- 按 modern 路径访问
- 继续复用当前 `nacos-client 3.x`

## 5. 只配某一类能力时，最少需要填什么

## 5.1 只用配置中心

至少填写：

- `spring.config.import=nacos:...`
- `spring.cloud.nacos.config.server-addr`
- `spring.cloud.nacos.username/password`，前提是服务端开启鉴权

可不填：

- `spring.cloud.nacos.discovery.*`

## 5.2 只用服务注册发现

至少填写：

- `spring.application.name` 或 `spring.cloud.nacos.discovery.service`
- `spring.cloud.nacos.discovery.server-addr`
- `spring.cloud.nacos.username/password`，前提是服务端开启鉴权

可不填：

- `spring.config.import`
- `spring.cloud.nacos.config.*`

## 5.3 同时用配置中心和服务注册发现

建议至少填写：

- `spring.application.name`
- `spring.config.import=nacos:...`
- `spring.cloud.nacos.config.server-addr`
- `spring.cloud.nacos.discovery.server-addr`
- `spring.cloud.nacos.username/password`
- `platform.nacos.compat.mode`

## 6. 最容易误配的点

1. `1.x accessToken` 不是手工填写。  
   当前代码必须通过 `username/password -> /nacos/v1/auth/login -> accessToken` 自动换取。

2. `spring.cloud.nacos.config.encode` 当前不会改变本地解析编码。  
   compat core 实际按 UTF-8 读取和解析配置。

3. `spring.cloud.nacos.config.import-check.enabled` 当前只是保留配置面。  
   compat core 本身不依赖它决定是否继续启动。

4. `accessKey/secretKey` 不是 `accessToken`。  
   它们只在 modern SDK 路径下真正传入客户端属性。

5. `config.server-addr` 和 `discovery.server-addr` 是分开的。  
   当前代码不会自动用一个去补另一个，建议两个都显式写。

6. `spring.application.name` 不只是日志名。  
   在没显式配置 `spring.cloud.nacos.discovery.service` 时，它直接决定注册到 Nacos 的服务名。

## 7. 推荐口径

如果你的目标是“同一套包同时兼容 `1.3.2 / 2.4.0 / 2.5.1 / 3.2.1`”，推荐统一口径是：

```yaml
platform:
  nacos:
    compat:
      mode: AUTO
      log-probe-detail: true
```

然后按实际能力补齐：

- 配置中心：`spring.config.import` + `spring.cloud.nacos.config.*`
- 注册发现：`spring.application.name` + `spring.cloud.nacos.discovery.*`
- 鉴权：`spring.cloud.nacos.username/password`

如果你的目标是“明确只连旧版本 `1.3.2 / 2.4.0`”，则更建议显式写：

```yaml
platform:
  nacos:
    compat:
      mode: LEGACY
```
