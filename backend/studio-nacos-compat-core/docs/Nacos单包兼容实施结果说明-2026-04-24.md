# Nacos 单包自适应兼容实施结果（2026-04-24 / 2026-04-25）

## 1. 目标与结论

当前 `cloud-parent-springboot3` 已实现同一套代码、同一套部署包对以下 Nacos 版本的兼容：

- `1.3.2`
- `2.4.0`
- `2.5.1`
- `3.2.1`

兼容分档结论如下：

- `1.3.2`、`2.4.0`：走 `legacy` 兼容层，只使用 HTTP/OpenAPI
- `2.5.1`、`3.2.1`：走 `modern` 路径，继续使用当前官方 `nacos-client 3.0.3` / gRPC

交付形态为单包自适应：

- 默认：`platform.nacos.compat.mode=auto`
- 可强制切换：
  - `platform.nacos.compat.mode=legacy`
  - `platform.nacos.compat.mode=modern`

## 3. 自动判代逻辑

`auto` 模式判定顺序如下：

1. 优先探测 modern 状态端点
2. 若 modern 状态端点不可用，则回退探测 legacy 状态端点
3. 根据最终探测到的版本号映射为 `LEGACY` 或 `MODERN`

当前使用的状态端点：

- modern 首选：`/nacos/v3/admin/core/state`
- modern 回退：`/v3/console/server/state`
- legacy：`/nacos/v1/console/server/state`

### 3.1 `2.5.1` 的特殊说明

`2.5.1` 实测中，modern 状态端点可能返回 `404`，但 legacy 状态端点会返回带版本号的状态信息。

兼容层当前处理方式是：

1. 先探 modern 端点
2. modern 端点不可用时，回退到 `/nacos/v1/console/server/state`
3. 若返回版本号属于现代代际，则仍判定为 `MODERN`

因此 `2.5.1` 虽然可能看见“v3 状态端点不可用”，但最终仍会走 modern gRPC 路线。

本轮已顺手收口日志语义：

- `auto` 模式下，若 modern 状态端点不可用但后续成功通过 legacy 状态端点判定版本，不再把这类情况记成误导性的 warning
- 只有“最终无法判定”时才记真正的探测失败

目录：

- `C:\dev\nacos\nacos321`

服务端额外前提：

- 需要用 JDK 17 启动
- 需要补 3 个 `--add-opens`

必需参数：

```text
--add-opens=java.base/java.lang=ALL-UNNAMED
--add-opens=java.base/java.lang.reflect=ALL-UNNAMED
--add-opens=java.base/java.util=ALL-UNNAMED
```

原因：

- `jraft` 会反射访问 `ArrayList.elementData`
- 不加时会抛 `InaccessibleObjectException`

实测通过：

- `platform-admin`
- `xxl-job-admin`
- `gateway-service`
- `studio-server`
- `studio-worker`
- modern 配置刷新

- 日志存在 `grpc client connection server: 127.0.0.1 ip, serverPort: 9848`
- `studio-server`、`studio-worker` 在 `18080/18081` 健康通过

结论：

- `3.2.1 => MODERN`
- root 主链和 `studio backend` 主链可用

## 6. Nacos 3.x API 差异

### 6.1 管理状态接口

`3.2.1` 可用：

- `GET /nacos/v3/admin/core/state`

### 6.2 服务列表接口

`3.2.1` 中：

- `GET /nacos/v1/ns/service/list` 可能返回 `501`

应改用：

- `GET /nacos/v3/admin/ns/service/list`

认证方式：

- 先 `POST /nacos/v1/auth/login`
- 再以 `Authorization: Bearer <token>` 调 `v3 admin`

## 8. 建议的启动口径

服务端启动建议：

- 各版本统一优先使用：

```bat
startup.cmd -m standalone
```

其中：

- `3.2.1` 需要按上文补 `--add-opens`
- `1.3.2`、`2.4.0`、`2.5.1` 可按各自现有目录直接起

业务服务建议保持：

- `platform.nacos.compat.mode=auto`

只有排障时再显式切：

- `legacy`
- `modern`

## 9. 最终结论

当前 `cloud-parent-springboot3` 已具备以下兼容能力：

- `1.3.2 / 2.4.0`：通过 legacy HTTP 兼容层完成服务注册、发现、配置读取与刷新
- `2.5.1 / 3.2.1`：通过 modern gRPC 路径复用官方 `nacos-client 3.0.3`
- `gateway-service` 与 `studio backend` 已并入同一套兼容判代体系

可以继续保持单代码线、单部署包，不需要再为不同 Nacos 版本分别维护多套客户端实现。
